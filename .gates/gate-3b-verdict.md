## Findings (by severity)

**[CRITICAL] ReportsController.php `documentLocationBuckets()` / `agedPayables()` (diff hunk `@@ +845..+905`, `d95e6cde2`) — AP by-location buckets are computed by an independent raw query that does not match `AgedPayablesService`, so they do NOT reconcile to `grand_total`.** The bucket query selects `documents` `whereIn('status',[Posted,Received])`, `type=PurchaseOrder`, amount `balance_due ?? total`, with **no** `document_date <= as_of`, **no** `balance_due > 0`, and **no** `whereJsonContainsKey('payload->auto_generated')` filter. But `AgedPayablesService::getOutstandingInvoices` (AgedPayablesService.php:102–121) counts only *Posted POs with balance_due>0* **plus** *auto-generated Received POs valued at a computed GR-IR accrual* (`autoGeneratedReceivedPurchaseOrdersWithAccrual`). Any tenant using goods-receipt/GR-IR (the standard supplier flow) has Received POs → the buckets include rows the report excludes and value auto-received POs at `balance_due??total` instead of the accrual → `sum(buckets) ≠ grand_total`. This is wrong money in a surface whose entire contract is "reconciles to the company-wide figure," and it is completely untested (no test hits `aged-payables?group_by=location`). Fix: derive the buckets from the *same* collection the service returns (add a per-location grouping to `AgedPayablesService`/`AgedPayablesData`), not a re-implemented query.
