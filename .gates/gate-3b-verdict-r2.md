### New findings

**[MINOR] apps/api/database/factories/LocationFactory.php:23 — `strtoupper($this->faker->lexify('LOC-???'))` yields only 26³ = 17,576 codes with no uniqueness guard; the `idx_locations_company_code` unique constraint (company_id, code) can collide.** The Wave 3 tests create 2+ locations per company, so combined PG runs intermittently fail (hit once at `MaturingInstrumentsTest.php:138`; re-run passed). Why it matters: order-dependent faker RNG state makes CI flaky, which can mask or falsely fail the aggregate reconciliation gate. Suggested fix: make the factory `code` a unique sequence (e.g. `'LOC-'.$this->faker->unique()->numerify('#####')` or an incrementing sequence).

**[MINOR] Test-coverage observation — no reconciliation test exercises the AP GR-IR accrual bucket.** The AP recon seeds (`billAt`, LocationReconciliationTest.php:230–231) create Posted POs with plain `balance_due`; no auto-generated `Received` PO valued at accrual is seeded, so the accrual-mutation branch of `locationBuckets()` is guarded only by construction, not by an assertion. Reconciliation still holds by construction; adding an accrual-valued Received-PO case would harden the guard. Non-blocking.
