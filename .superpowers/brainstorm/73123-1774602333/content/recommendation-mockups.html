Implementation approach: Build both, toggle via config

  • Company setting: smart_prompts_variant: "inline" | "toast" | "off"
  • Both variants share the same backend service + hook — only the UI component differs
  • Dev branch only — test both variants, settle on one before merging to main
  • ℹ️ button on each card opens a popover with: strategy reason, ingredient overlap %, or routine step explanation
  • Tapping the card itself → adds product to cart immediately

Both variants use the same useCartRecommendations hook and SmartPromptCard atom — only the container layout differs. This keeps the A/B test clean.
