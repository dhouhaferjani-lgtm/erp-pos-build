# M4 — SV-10 blind-mode leak audit

## Scope and test method

This audit follows rendered values through the production caller rather than inferring safety from component names. The acceptance question is narrow: while `require_blind_cash_count` is true and before **Commit Counts**, does any rendered surface disclose an expected-cash or variance magnitude?

The regression at `apps/pos/src/components/pos/CashReconciliationSection.test.tsx:276` enters an actual count that creates a critical `-60.00` variance, then asserts that the Expected/Variance columns, `-60.00`, reveal summary, reason prompt, and manager-PIN prompt are absent before Commit Counts and present afterward. A temporary mutation removing the `committed` guards made that test fail on the pre-commit reason prompt; restoring the guards returned it green.

## Result

No reachable cashier pre-commit surface directly renders expected-cash or variance magnitude under blind mode. No production fix was required, and the existing legacy-card defence was not changed. M4 adds rendered coverage for the critical severity/reason/PIN path and records the separate manager/demo screen for follow-up rather than expanding this lane into a close-screen redesign.
