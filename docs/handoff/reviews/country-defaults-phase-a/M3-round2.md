## Register — round 2

**1 — P3 — `docs/handoff/CODEX-DISPATCH-country-defaults-phase-a-2026-08-10.md:404` and `:412` vs `DefaultsEditorController.php:164-173` — CONFIRMED — a brief-mandated capability and its required test were deleted, and the brief was not amended.**

Failure scenario is procedural, not runtime: M7's whole-branch gate or a later reviewer diffs the brief against the tests, finds a named required test absent, and either re-adds a role-change path (reopening the four-eyes hole) or blocks the wave. Fix: record the deviation in the brief/§M3 or in `progress/country-defaults-phase-a.progress.yaml` so it survives as an accepted deviation rather than a gap.

**2 — P3 — `AssignmentController.php:103-106` — CONFIRMED — the sibling conflict classifier keeps the loose SQLite matching this same round removed from `TemplateRowController`.**
`556b9771e` hardened the row classifier to *exact* two-column signatures with a terminal boundary plus a `getSql()` table check, on the finding that `str_contains` accepts prefixes and unrelated statements. `isAssignmentUniqueConflict()` was left on two bare `str_contains` checks for `country_template_assignments.country_code` and `…domain`, with no signature boundary and no statement check. Failure scenario: any future `country_code_suffix`-style column, or any `QueryException` raised on a different statement in the same request whose message embeds both strings, is translated to `409 ASSIGNMENT_CONFLICT` and never reaches monitoring. Unreachable with today's schema (the table carries exactly one composite unique), which is why this is P3 and not P2 — but it is the same defect class, one file away, and the row classifier now has regression tests the assignment classifier does not.

**3 — P3 — `TemplateController.php:133` — CONFIRMED — the validation report emits raw untranslated English domain-exception text on a user-facing endpoint.**

**4 — P3 — `EnsureCentralAdmin.php:25-32` applied at `routes/api.php:44` — CONFIRMED — flipping the flag off also blocks the editor's own logout, and does not revoke the token.**
Once `external_editors_enabled` goes false, a live editor token gets 403 on `POST /admin/auth/logout`, so the holder cannot revoke their own credential; the PAT persists to `config/sanctum.php` `expiration` (30 days) and becomes live again the moment the flag is flipped back on. The report states this is intentional — "the middleware denies rather than revokes … without making a config flip perform a hidden one-way credential mutation" (`:1229-1231`) — and I accept the reasoning: every boundary now fails closed, so residual risk is a stale-credential window, not access. Worth one line in the ops runbook when the flag is used on staging.

**5 — P3 — `DefaultsEditorController.php:31`, `:65`, `:102` — CONFIRMED — stale `#[CrossTenantRoute]` provenance text and one dead catch branch.**
The attribute at `:31` still reads "Lists **non-super-admin** central accounts" and `:65` "Changes a **non-super-admin** central account lifecycle and revokes affected central tokens" — both describe the pre-fix behavior; the endpoints are now `defaults_editor`-only and tokens are revoked on disable/reset only. ## Bypasses attempted that FAILED (the code held)

- **Reaching a `support_approver` through the surviving editor verbs.** All three selectors are role-scoped *before* `lockForUpdate()`, so the 404 precedes the lock and the write; `assertDatabaseMissing('admin_audit_logs', ['entity_id' => $approver->id])` proves no audit noise either.
- **Re-opening four-eyes by minting a `defaults_editor` on an allowlisted approver email.** `ConfiguredApproverSet::allows()` requires `role === support_approver` (`:38`), and `super_admins.email` is uniquely indexed, so the allowlisted address is already taken by the real approver — `strtolower(trim($email))` at `:136` normalizes any case-variant onto that same collision (409, not a second account).
- **Mass-assigning `email`/`password` through `PUT /editors`.** Both are `$fillable` on `SuperAdmin` but the controller passes `safe()->only(['name','is_active','role'])` and the FormRequest declares no such keys.
- **Escaping the flag via a pre-existing token.** `DefaultsEditorLoginFlagTest.php:40-59` uses a real minted token, not `actingAs`; all three boundaries deny.
- **Escaping the flag via a non-`EnsureCentralAdmin` admin route.** Every `auth:sanctum-admin` route in the repo carries either `super_admin` (`EnsureSuperAdmin`, exact-role) or an explicit `central_admin_role:` list; `defaults_editor` appears in exactly one list.
- **500 on `POST /publish` via illegal scope algebra** (`certified_country_codes: ['TN','FR']` or `['*','FR']`). `CertificationScope` throws `InvalidArgumentException`, which is not a `DomainException` and would escape `publish()`'s narrowed catch — but `TemplatePublishingService.php:52-54` wraps it into `DomainException` first, so it lands as 422. Held.
- **500 on `GET /validation?scope=…`** after the catch narrowing: `ValidateTemplateRequest::after()` pre-validates the exact same `CertificationScope` construction the controller performs at `:129` (regex guarantees no empty segments, so the request's `array_map('trim',…)` and the controller's `array_filter(array_map('trim',…))` produce the identical list) → 422 before the controller runs.
- **Silent row loss via duplicate codes in `PUT /rows`.** `rowInsertionOrder()` keys by raw code and would collapse duplicates, but `rows.*.code` carries `distinct` (`UpsertTemplateRowsRequest.php:31`); whitespace variants survive validation yet collide on the trimmed value at the named unique → 409, not data loss.

- **Central rows landing in a tenant DB.** `AdminTemplate`, `AdminTemplateAccount`, `CountryTemplateAssignment`, `SuperAdmin` and `AdminAuditLog` all use Stancl's `CentralConnection`; `CentralConnectionUnderTenancyTest.php:48-105` swaps the default connection to an in-memory probe under an initialized tenancy and proves every write stays central.
