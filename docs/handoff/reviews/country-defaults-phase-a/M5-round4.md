## Findings register

**1. P2 — `apps/api/phpunit.xml:20-24` + 19 test classes — CONFIRMED.** The F-6 labeling guard (`FrozenSeederProvisioningIsolationTest.php:110-130`) forced `#[Group('historical-compat')]` onto every test class that so much as *names* a frozen seeder, and the implementer complied by labeling live, current-behavior suites as historical. The group did not exist anywhere before this branch (`git grep -c historical-compat 7d85232cc -- apps/api/tests` → zero hits); it was invented here and now covers `Feature/Treasury/InstrumentAccountResolverTest.php:21`, `Feature/Treasury/PayableInstrumentAccountsTest.php:22`, `Feature/Accounting/InvoiceGLIntegrationTest.php:60`, `Feature/Accounting/DocumentGlPreflightTest.php`, `Feature/Accounting/DocumentCancellationGlReversalTest.php`, four `Backfill*Test` migration suites, `Feature/Document/CancelRefusedOnNonOpenVatPeriodTest.php:61`, `Feature/Document/Types/{Invoice,CreditNote}DocumentTest.php`, `Feature/Expense/ExpenseCategorySeederTest.php:28` — and, self-defeatingly, **this wave's own required tests**: `Feature/CountryDefaults/ExpenseCategorySeederLoudFailureTest.php:20` (an M5 brief-mandated test) and `Unit/CountryDefaults/ProvisioningRequiredPurposesV1ConformanceTest.php:38` (the M1 conformance suite). None of these are historical-compat tests; they use a frozen seeder only as a chart fixture. **Failure scenario:** `phpunit.xml` already carries a `<groups><exclude><group>sweep-progress</group></exclude></groups>` block — the project's established idiom for pruning a suite. A single line adding `<group>historical-compat</group>` (the obvious reading of the name, and exactly why one labels a group "historical") silently removes the entire invoice-GL integration suite, both treasury instrument-account suites, the VAT-period cancel refusal suite, the four GL backfill migration suites, and both of this wave's own gate tests from every `composer test`, preflight, and CI run — with a green result. The guard needs a marker whose name states what it means (`frozen-seeder-fixture`), or the fixture use must be exempted from the labeling requirement.

**2. P2 — `apps/api/app/Modules/Accounting/Application/Services/ChartOfAccountsService.php:67-76` — CONFIRMED.** `previewLegacyExistingChartRepair()` is a **public, committing write method** whose only protection is `DB::connection()->transactionLevel() < 1` (`:69`). That predicate is satisfied by *any* open transaction, including a committing one; it does not and cannot establish that the caller will roll back. The method itself opens no transaction (contrast `seedForCompany()`, which wraps its identical legacy call in `DB::transaction()` at `:53-57`). **Failure scenario:** any later caller writes `DB::transaction(fn () => $this->charts->previewLegacyExistingChartRepair($company))` — the dominant idiom in this very file — the guard passes, and the frozen TN/FR/Generic seeder inserts and reparents rows on an **existing** company's chart while `provisioning_enabled` is true. That is a direct breach of the wave's `no-existing-company-mutation` standing constraint (`country-defaults-phase-a.progress.yaml:26-29`) and of the method's own docblock (`:63`), and nothing detects it: `NoExistingCompanyMutationTest.php:22-52` only exercises `seedForCompany()`, no test asserts the `LogicException` fires outside a transaction, and under `RefreshDatabase` every test already runs at `transactionLevel() >= 1`, so the guard is vacuous in the entire suite. The seam should own its transaction and roll back internally (returning the counts), or the legacy seeder call should stay inside the command that guarantees the rollback.

**3. P2 — `apps/api/app/Console/Commands/SeedChartsCommand.php:115-119,131-139,168-175` and its docblock `:36-53` — CONFIRMED.** The reinstated dry-run reports a baseline it can never apply, with no marker saying so. Under flag-true the preview deliberately ignores the assigned template — `test_template_provisioning_legacy_dry_run_ignores_stale_assignment_without_writes` (`SeedChartsCommandTest.php:254-278`) pins exactly that — yet stdout is byte-identical to the pre-flip preview: `[DRY-RUN] Company <id> (TN): 12 created, 0 promoted, 3 reparented.` **Failure scenario:** post-Release-2, an operator working the treasury-phase-2 procedure the command's own docblock cites (`:17-24`) runs `tenants:run accounting:seed-charts --option=dry-run=1`, reads "12 created", and concludes those twelve accounts are the gap against the platform default. They are the gap against the *retired legacy* chart; the assigned template may specify a different set. The operator then runs the apply form and gets `FAILURE` with no successor procedure named. The command's stated "Honest reporting" contract (`:49-53`) is not met, and the docblock still only says the command "fails closed" — it never mentions that dry-run survives, that it reports legacy semantics, or what to do instead. A `$this->warn()` on the `$dryRun && $templateProvisioningEnabled` branch plus two docblock lines closes it.

## Bypasses I attempted that FAILED (the implementation held)

- **Admin API poisoned by the new 503 mapping.** `TemplateAssignmentService.php:73` also throws `TemplateRecertificationRequiredException`, which now extends the 503-mapped base — I expected a super-admin `POST` assignment refusal to degrade from an actionable 409 into "Company setup is temporarily unavailable". It does not: `AssignmentController.php:78-82` catches `DomainException` and returns `409 ASSIGNMENT_CONFLICT` before the global renderer is ever reached. `VerifyCountryDefaultsCommand.php:101` is console-only.
- **Render-order flattening.** `bootstrap/app.php:883` is registered ahead of the generic `DomainException` handler at `:900`; Laravel 11 matches in registration order, so the 503 wins. No earlier handler in the file matches these classes.
- **Frontend 5xx side effects from the status change.** `apps/web/src/lib/api.ts:249-251` only `console.error`s on `>= 500` — no logout, no maintenance redirect, no retry storm (company creation is a TanStack mutation, `retry: 0` by default).
- **Message leakage through the new envelope.** Every refusal path is covered by an `assertDontSee` on its distinctive internal token, and the internal detail survives for operators via `Log::error` with `exception_class`/`exception_message` (`bootstrap/app.php:886-890`).
- **`is_system` promotion regression from the `$matchedByCode` fix.** Walked both branches of `GenericChartOfAccountsSeeder.php:40-70` against `TemplateChartOfAccountsSeeder.php:33-58`: parity is exact, and the code-match promotion path is still exercised (`TemplateChartOfAccountsSeederSemanticsTest.php:47`).
- **Connection mismatch in the preview guard.** `SeedChartsCommand` opens via injected `DatabaseManager::beginTransaction()` (`:107`) while the guard reads `DB::connection()->transactionLevel()` (`ChartOfAccountsService.php:69`) — both resolve the same default connection, so the guard is not trivially defeated by connection skew.
- **Rule 19 / horizon / DI sweep of the round-4 delta.** No float touches money or quantity; no new migration, no new named queue; no `app()` in production code (`Log`/`DB` facades only, at bootstrap and in a service that already uses `DB::`); en+fr both present for the one new user-facing string.
