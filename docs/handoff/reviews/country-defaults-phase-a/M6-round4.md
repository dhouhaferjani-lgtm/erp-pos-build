### Findings

**1 — P3 — CONFIRMED — `apps/web/src/features/admin/country-defaults/pages/TemplateEditorPage.tsx:202`**
The round-3 fix split 422 out but left every *other* non-200 collapsed into "Validation is temporarily unavailable. **Try again.**" — including **403** and **404**, for which retrying is futile. Tenancy-authz-relevant case: a `defaults_editor` whose feature flag or account is deactivated mid-session (`EnsureCentralAdmin` 403s) keeps a rendered editor because `templateQuery.data` is still cached, and the validation panel tells them the service is having a temporary problem rather than that their access was revoked. Same for a template archived/deleted by a concurrent `super_admin` (`findOrFail`, `TemplateController.php:123` → 404). `countryDefaultsErrorKey` (`lib/apiError.ts:9-16`) already maps 403 → `errors.forbidden` and the namespace already has the key — this is a one-line widening of the same ternary, not new copy. Rated P3, not P2: unlike the round-3 422 case this is not reachable by valid operator input, only by a concurrent privilege/state change.

**2 — P3 — CONFIRMED — `apps/web/src/features/admin/country-defaults/__tests__/TemplateEditorPage.test.tsx:189-202`**
The new 422 test depends on keystroke timing to line its `mockResolvedValueOnce` / `mockRejectedValueOnce` queue up with the debounce. `user.type(…, 'TN,FR')` passes through the complete-scope state `TN` (`COMPLETE_SCOPE_PATTERN`, `:23`); if any inter-keystroke gap exceeds `VALIDATION_DEBOUNCE_MS` (300 ms) on a loaded runner, `TN` consumes the rejection and `TN,FR` gets the default `undefined` mock. It fails loudly (`findByText` timeout) rather than passing vacuously, so it is a CI-flake note, not a correctness hole. Typing `TN` then `,FR` against an explicit `mockRejectedValue` (not `…Once`) removes the coupling.

**3 — P3 — CONFIRMED — `apps/web/src/features/admin/country-defaults/pages/AssignmentsPage.tsx:32-39`** (carryover, not introduced in round 4)
The brief requires "out-of-scope templates not offered". `optionsFor` deliberately prepends the currently-assigned template to the `<Select>` when it is no longer eligible (drifted data). It is genuinely *in* the option list, but it is not exploitable: the re-point button is disabled when `candidate === row.template_id` (`:60`), the option is scoped to that row only, and the backend re-validates on `PUT assignments/{countryCode}`. Worth recording explicitly on the P3 ticket rather than leaving it implicit, since the brief's wording reads absolutely.
