## Required Findings

- **Important — `apps/pos/src/lib/sync/syncService.ts:164,178-184`:** the terminal snapshot was captured before an awaited persistence write, then applied unconditionally. A reset, terminal switch, or concurrent terminal refresh during that await could resurrect a detached terminal or overwrite newer fields. Re-read/reconcile after the persistence boundary and never apply a stale snapshot after it.
- **Important — `apps/pos/src/lib/sync/syncService.ts:183-184`:** persistence happened before in-memory enforcement. If storage failed, the safety block never reached the stock gate and the otherwise-successful pull was mislabeled as failed. Enforce in memory first and make persistence best-effort.
- **Important — `apps/pos/src/lib/sync/__tests__/syncService.test.ts:754-899,1040-1071`:** the existing fiscal-regression test used a terminal id that did not match the seeded store, so it never exercised the projection call in the `FiscalRegressionError` success path. Add matching-id coverage of both store and persistence.
