# IMP-1 realignment log

2026-09-11 — §4.10 / G-1: correction exports now select failed and warning rows, preserve source-header spelling/order, and append `_status`, `_code`, `_message` in CSV and XLSX. `POST /imports` accepts `reimport_of`; same-tenant/company and entitlement checks precede mapping reuse. `column_mapping` is validated injectively; source-header order is retained in typed `options.source_headers` because PostgreSQL JSONB objects do not preserve key order. A `partially_completed` status distinguishes row/finalization errors after successful writes, including an effective display status for older failed jobs. Full report remains a separate three-sheet workbook. G-8 convention integration and the underlying supplier currency-context bug remain ticketed.

2026-09-12 — fix round 1 (gate r1). **`GET /api/v1/imports` and `GET /api/v1/imports/{id}` now return `error_code`** (the `ImportErrorCode` value, or `null`) alongside `error_message`. `error_code` is the operator channel and is what any client must render, translated; `error_message` is the support/diagnosis channel and carries raw exception text (class names, file paths, full SQLSTATE strings with key values) — it must never be shown. Every terminal failure stamps a code, so a non-null `error_message` implies a non-null `error_code`. **`GET /api/v1/imports/{id}/failed-rows.{csv,xlsx}` is now ephemeral**: the generated artefact is deleted as the bytes are streamed, and any orphan is removed by `DELETE /api/v1/imports/{id}` and by `imports:purge-expired` — a client must not assume a stable server-side file behind that URL. No request shape changed; both are additive/behavioural.
