## 1. Purpose

**Scope reframe in v2:** We do not yet know whether Nénupharma uses WooCommerce, PrestaShop, Shopify, or none. Building a concrete WooCommerce adapter against an unknown platform choice is premature scope. **This sprint ships only the shared infrastructure** — the `ChannelAdapter` port, the framework around it, the admin UI, the credential storage, the reconciliation skeleton. Concrete adapter classes ship in a follow-up sprint after the client confirms their platform.

What we build:
- Generic `ChannelAdapter` interface + DTOs
- `Channel`, `ChannelCredential`, `ChannelProductMapping`, `ChannelOrder`, `ChannelSyncOperation` domain entities + migrations
- Outbound dispatcher framework (debounced, idempotent, retryable, queue-backed)
- Inbound webhook framework (signature-verified, replay-protected, queue-handed-off)
- Encrypted credential storage (Laravel encrypted casts)
- Admin UI: list channels, configure channel (adapter-type-agnostic), per-product mapping screen, sync status dashboard
- Reconciliation job skeleton (adapter-agnostic; concrete diff logic ships with adapters)

What we DON'T build this sprint:
- Any concrete adapter (`WooCommerceChannelAdapter`, `ParadealsPublicationAdapter`, `ShopifyChannelAdapter`)
- No `automattic/woocommerce` composer dependency
- No platform-specific webhook signature implementations (signature framework only)

**Patterns to mirror:**

- `PlatformHttpClient` style for any future outbound HTTP — circuit breaker (3 fails / 30s) + retry on 429/5xx + 5s connect + 10s total
- `DB::afterCommit(fn() => event(...))` for event emission
- Tenant-scoped listener — resolves tenant from event, executes within tenant context
- Encrypted credentials — Laravel encrypted casts
- Idempotency keys — every outbound dispatch carries a tenant-scoped idempotency key

**Constraints:** hexagonal, constructor injection, strict typing, enums for status, TDD, PHPStan level 8.
**Migration placement:** every new table per this spec lives in `database/migrations/tenant/` (per topology contract).

## 3. Domain model

### New entities (all in tenant DB)

**`Channel`**
- `id` (UUID), `company_id` (FK `companies` within tenant DB — corrected per round-2 P2-A; not `locations`), `name`, `adapter_type` enum (placeholder string field — see Enum note below)
- `is_active`, `connection_status` enum (`Pending`, `Connected`, `Failed`, `Suspended`)

**`ChannelCredential`** (encrypted)
- `id`, `channel_id`, `credential_type` enum (`OAuthToken`, `ApiKey`, `ConsumerKeySecret`, `Custom`)
- `encrypted_payload` (Laravel `encrypted` cast)
- `expires_at` (nullable)

**`ChannelProductMapping`**
- `id`, `channel_id`, `product_id`, `variant_id` (nullable — T2 dep)
- `is_published` (bool), `published_at`, `last_synced_at`, `last_sync_hash` (idempotency)
- `external_id` (nullable string — set by concrete adapter when product synced)
- `price_override` (nullable — for future adapter-side per-channel pricing; T11 PricingStrategyResolver will consume)
- `quantity_cap` (nullable — for future per-channel inventory reservation; structure-only)

**`ChannelOrder`** — generic inbound order envelope
- `id`, `channel_id`, `external_order_id`, `received_at`, `processed_at` (nullable)
- `status` enum (`Pending`, `Processed`, `Failed`, `Ignored`)
- `payload` JSONB (raw inbound payload)
- `document_id` (FK Document within tenant DB, nullable — set when promoted)
- `error_message` (nullable)

**`ChannelSyncOperation`** — outbound dispatch log
- `id`, `channel_id`, `operation_type` enum (`ProductPush`, `StockPush`, `PriceUpdate`, `OrderStatusUpdate`)
- `payload_hash`, `idempotency_key`, `dispatched_at`, `acknowledged_at`
- `status` enum (`Pending`, `Acknowledged`, `Failed`, `Retried`)
- `attempt_count`, `next_retry_at`

### Enums

- `AdapterType` — initially empty registry (no concrete adapters this sprint); typed as string in DB; the `AdapterRegistry` service knows what's registered. When future adapters land, they register their adapter_type string.
- `ChannelConnectionStatus` (Pending, Connected, Failed, Suspended)
- `CredentialType` (OAuthToken, ApiKey, ConsumerKeySecret, Custom)
- `ChannelOrderStatus` (Pending, Processed, Failed, Ignored)
- `SyncOperationType` (ProductPush, StockPush, PriceUpdate, OrderStatusUpdate)
- `SyncOperationStatus` (Pending, Acknowledged, Failed, Retried)

### Migration placement

All new tables → `database/migrations/tenant/`. Per the topology contract, FKs are intra-tenant only.

## 4. Public contracts

### Port interface (generic, adapter-agnostic)

```php
interface ChannelAdapter
{
    public function adapterType(): string;
    public function pushProduct(Product $product, ?ProductVariant $variant, ChannelProductMapping $mapping): SyncResult;
    public function pushStock(StockUpdateDTO $update): SyncResult;
    public function pushPriceUpdate(PriceUpdateDTO $update): SyncResult;
    public function pullOrders(Channel $channel): Collection;
    public function updateOrderStatus(string $externalOrderId, OrderStatusUpdateDTO $update): SyncResult;
    public function testConnection(Channel $channel): ConnectionTestResult;
}

// Concrete adapter classes (WooCommerce/PrestaShop/Shopify/Paradeals) are
// FUTURE sprint deliverables. This sprint ships the contract only.
```

### Adapter registry (sprint deliverable)

```php
class AdapterRegistry
{
    public function register(string $adapterType, string $adapterClass): void;
    public function resolve(string $adapterType): ChannelAdapter;
    public function listRegistered(): Collection<string>;
}
```

This sprint: registry exists, has zero adapters registered. Future sprints: each new adapter registers itself in its service provider.

### Application services

```php
ChannelService
  ::create(CreateChannelCommand): Channel
  ::testConnection(UUID $channelId): ConnectionTestResult  // delegates to registered adapter
  ::publishProduct(UUID $channelId, UUID $productId, ?UUID $variantId, array $overrides): ChannelProductMapping
  ::unpublishProduct(UUID $channelId, UUID $productId, ?UUID $variantId): void
  ::manualResync(UUID $channelId): SyncResult

ChannelOrderIngestService
  ::ingest(string $externalOrderId, array $payload, Channel $channel): ChannelOrder
  ::promote(UUID $channelOrderId): Document  // see "T3 ↔ T4 promote contract" below
```

**T3 ↔ T4 `promote` contract (pins round-2 P2-B):** `ChannelOrderIngestService::promote` is the owner of Document materialization. It calls `OrderRoutingService::routeFromChannelOrder($channelOrderId)` to obtain a `RoutingDecision`, then materializes the `Document` with `location_id = decision.chosen_location_id`, then writes `RoutingDecision.document_id` back. **T4's `OrderRoutingService` does NOT construct Documents** — it returns routing decisions only. T3 owns Document creation; T4 owns the routing decision and its audit trail.

When no adapter is registered for a channel's `adapter_type`, `ChannelService` operations return a clear error: "No adapter registered for type X. Concrete adapters ship in a follow-up sprint."

### Events

- `ProductPublishedToChannel`, `ProductUnpublishedFromChannel`
- `ChannelOrderReceived`, `ChannelOrderPromotedToDocument`
- `ChannelSyncDriftDetected` (reconciliation job)
- `ChannelDispatchFailed` (when adapter dispatch fails)

### Jobs

- `DispatchProductToChannelJob` — listener-triggered, debounced (coalesce bursts within 5s window)
- `DispatchStockChangeToChannelJob` — listener-triggered on `StockMovementRecorded`, debounced
- `IngestChannelOrderJob` — future-adapter webhooks dispatch this
- `ChannelReconciliationJob` — nightly per channel; skeleton calls adapter's read methods, flags diffs

### REST + webhook endpoints

- `POST /api/v1/channels` — create
- `GET /api/v1/channels` — list
- `POST /api/v1/channels/{id}/test-connection` — calls registered adapter; returns error if no adapter
- `POST /api/v1/channels/{id}/products/{productId}/publish` — supports variantId in body
- `POST /api/v1/channels/{id}/products/{productId}/unpublish`
- `POST /api/v1/channels/{id}/resync` — manual full resync
- `GET /api/v1/channels/{id}/sync-operations` — operation log
- `GET /api/v1/channels/{id}/orders` — staged orders
- `POST /api/v1/channels/{id}/orders/{orderId}/promote`
- Generic webhook receiver: `POST /webhooks/channels/{channelId}` — signature-verified via configurable per-adapter strategy; queues `IngestChannelOrderJob`. **Future adapter sprints add concrete signature strategies; this sprint provides the framework + a `NullSignatureStrategy` for testing.**
