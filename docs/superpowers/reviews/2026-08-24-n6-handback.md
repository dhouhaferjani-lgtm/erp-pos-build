**Adjacency as shipped** (`DocumentStatusMachine::allowedTargetsOf`):

```
draft      → confirmed, cancelled
confirmed  → draft, posted, cancelled          ← Paid DELIBERATELY ABSENT
posted     → paid, cancelled
paid       → posted                            ← refund / instrument-cancel reopen ONLY
cancelled  → (terminal)
received   → (out of Phase-1 scope: no caller in this lane writes it)
```
Self-loops are never allowed; idempotence is the caller's responsibility (`post()`/`cancel()` already short-circuit).

**`repairNeverPostedToConfirmed()` (`paid → confirmed`) is deliberately NOT in the map.** It repairs a state the map forbids reaching; putting it in the graph would legitimise downgrading a genuinely sealed invoice. Its precondition (`status = Paid` AND never sealed) is checked inside the method, not trusted from the caller.

**PHPStan rule scope, stated honestly.** Two checks, both statically decidable, no allow-list sprawl:
- `DocumentStatus::Paid` written to `Document::$status` anywhere outside `DocumentStatusService` → error `document.status.paidDirectWrite`. Measured: all 11 pre-lane `Paid` writes were in Treasury (`grep DocumentStatus::Paid app/`), so one allowed class suffices.
- `DocumentStatus::Posted` written to `Document::$status` from anywhere under `App\Modules\Treasury\` → error `document.status.treasuryPostedWrite`. Treasury must not decide a document was posted.

**TRIAGE #27 gap fixed:** the WorkOrder precedent matches only `PropertyFetch` assignment. This rule also matches `update([...])`, `fill([...])`, `forceFill([...])` array literals — which is what the real writers used (two `update()`, two `forceFill()`). Value matching is **type-based** (`$scope->getType(...)->describe(precise())`), so an indirection through a local variable is still caught (fixture proves it). Boundary, stated so a green run is not over-read: a value PHPStan cannot resolve to a single enum case is not reported; PHPStan analyses `app/` only, so migrations/seeders/tests are outside its view; raw SQL / `DB::table()` writes are outside the rule's shape entirely — the DB CHECK is the backstop for those.

**DB CHECK scope:** VALUE DOMAIN only, not the adjacency. Encoding edges in SQL needs the OLD row, i.e. a trigger, and `documents` already has one (`trg_document_immutability`) whose widening is the separate owner-tracked C-8 lane.
