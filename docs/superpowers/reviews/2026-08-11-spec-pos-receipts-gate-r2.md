# POS receipts/reporting spec adversarial gate — round 2

## 1. Gate verdict — FAIL

r2 contains the requested correction sections and correctly fixes several load-bearing claims, including the narrower `TerminalController` collection-gate claim, `companies.timezone` being non-null, the rounding-aware totals equation, and `RequirePermission` any-of behavior. It is still not build-ready. Binding sections conflict on the receipt type API, the exhaustive wire allowlist omits fields required elsewhere, the POS sidebar re-key names the wrong permission for Tables, the A-1 sidebar any-of gate is not expressible as specified, and multiple tests assert shapes or storage names that contradict the spec or source. Consequently §9 accurately records that edits were made, but its statements that all 15 fixes are applied and nothing was skipped are not accurate.
