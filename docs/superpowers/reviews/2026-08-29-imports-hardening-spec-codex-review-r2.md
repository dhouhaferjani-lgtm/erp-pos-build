# Session G imports hardening — adversarial spec review, round 2

**Baseline reviewed:** `a4ceeb0f5`. Current source code under `apps/api`, `apps/web`, `apps/pos`, and `packages/shared` is unchanged from that baseline; the reviewed change is the DRAFT r2 design.  
**Verdict:** **REWORK**.

The rework closes the barcode-index ruling, lifetime uniqueness, name identity, SKU allocation, country backfill, mapping injectivity, and several consumer-census defects. It does not yet define a safe executable path for exact XLSX decimals, durable outcomes, opening correction, M6 deployment, CompositeItems entitlement, or R10's separate opening-balance wizard. Those are blockers, not lane-detail polish.

## Migration sweep

- **M1/M2/M3:** the new company scopes are weaker than the intact tenant uniques; their census-then-refuse/forward-only pattern is sound. M2 correctly reproduces only the active-row SKU predicate and leaves barcode untouched. They have no data-order dependency on each other.
- **M4:** additive and nullable; it may run independently of M1-M3 because linked entities already carry `company_id`. Its mixed-evidence policy must change per G-R35. Failed second-company F-BUG-1 rows have no committed entity links, so they remain NULL on a multi-company tenant and do not abort.
- **M5:** additive; its application behavior depends on M1 having landed because generated/manual product inserts rely on `products_company_id_sku_unique` for exact catch/retry. That wave order is present.
- **M6:** depends operationally on M4/G-3b for company-correct census/execute, and must be split/backfilled per G-R27. As a single migration edited in two auto-deployed waves it is not forward-deployable.
- **M7:** independent, additive, and correctly performs the country backfill inside the migration.
- **Known staging shape:** none of M1-M7 should abort solely because of the failed second-company imports or code-less default locations. The old unique rejected the former; none of these migrations requires a location code. Only an actual census hit from missing/drifted constraints or manually damaged data should intentionally refuse M1-M3. The blanket claim that *every* migration is self-guarding/idempotent is nevertheless stronger than the briefs: M5/M6/M7 do not state their `hasTable`/`hasColumn`/index guards, while PostgreSQL's normal migration transaction gives rollback/retry rather than arbitrary rerun idempotence (`docs/superpowers/specs/2026-08-29-imports-hardening-design.md:1651-1656`; `apps/api/vendor/laravel/framework/src/Illuminate/Database/Migrations/Migrator.php:426-451`).

## VERDICT: REWORK

A spec r3 is required because blockers remain. The gate conditions are:

1. Replace G-8's reader sketch with an exact, mapped, cell-type-complete XLSX contract and a deliberate `.xls` policy (G-R25).
2. Make terminal row outcomes atomic with each entity/no-op decision, and split/backfill the migrations so every deployed wave is immutable (G-R26/G-R27).
3. Define one module-safe opening-correction transaction including row outcome, aggregate cost behavior, and reservation-safe quantity invariants (G-R28/G-R29).
4. Apply CompositeItems entitlement through both controllers and every create/template/preview/execute/show/resume surface (G-R30).
5. Move R10 guidance onto the actual Parties and Opening Balance wizard/service paths, using posted/mapped payloads as the echo authority (G-R31).

## Deliberately NOT taken

- No objection to variant-SKU-only M2, unchanged barcode constraints, or the decision not to add product-barcode uniqueness in this program. G-R37 asks only for deterministic refusal when unconstrained brownfield data is ambiguous.
- No objection to the R2 name-as-identity ruling for rows with neither SKU nor barcode; OQ-G-21 accurately exposes the merge tradeoff.
- No demand for a second sign-rule function. For Parties, `PartiesRowMapper::toBalancePayloads()` is already the single implementation used by posting; preview should format its returned payload. A new pure function is warranted only if both preview and mapper delegate to it—never as a second implementation. `HistoricalOpeningSideReader` remains a post-time AR/AP-side reader, not a sign oracle.
- No objection to XLSX header comments: the installed PhpSpreadsheet Xlsx writer supports them. The defects are text-cell binding, source/locale ownership, and the CSV marker rule.
- No claim that F-BUG-1's failed second-company rows or code-less locations should abort M1-M7. They should not; census refusal remains appropriate only for real constraint drift/damage.
- No rejection of Laravel nested transactions or `ProductCostLock`'s sorted advisory-lock contract. The unresolved issue is transaction ownership across correction and Import-row truth, plus aggregate cost/reservations.
- No request for POS SQLite changes, report rewrites, a new queue, a second Parties writer, a clear token, or interactive mid-run duplicate prompts.
- No finding for prose length. The defects above are contract, ownership, migration, or source-code mismatches.
