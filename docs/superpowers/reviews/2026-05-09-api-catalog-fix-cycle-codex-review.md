### F1 - api.catalog.021 regression test does not hit the registered variant route

`tests/Feature/Catalog/CatalogTenantIsolationTest.php:1319-1340` is the only selector for api.catalog.021's variant-owned-by-composite-item path, but it sends `PATCH /api/v1/composite-item-variants/{id}` at `tests/Feature/Catalog/CatalogTenantIsolationTest.php:1330-1333`. The registered routes are `PATCH /api/v1/variants/{id}` and `DELETE /api/v1/variants/{id}` at `app/Modules/Catalog/Presentation/routes.php:45-46`; `rg -n "composite-item-variants|variants/\\{id\\}|CompositeItemVariantController"` found no production route for `composite-item-variants`, only the test path and the `variants/{id}` routes. Because the test expects 404, a router-level 404 satisfies the assertion without executing `CompositeItemVariantController::update()`. This means the claimed green test does not prove the `whereHas('compositeItem', ...)` tenant/company predicate in `app/Modules/Catalog/Presentation/Controllers/CompositeItemVariantController.php:86-91`.

The same callsite group still has no effective cross-tenant selector for `index()` or `store()` parent `CompositeItem` reads at `app/Modules/Catalog/Presentation/Controllers/CompositeItemVariantController.php:33-36` and `app/Modules/Catalog/Presentation/Controllers/CompositeItemVariantController.php:55-58`, and no selector for `destroy()` at `app/Modules/Catalog/Presentation/Controllers/CompositeItemVariantController.php:125-130`; `rg -n "composite-item-variants|variants/\\{id\\}|CompositeItemVariantController" tests/Feature/Catalog` returned only the ineffective `CatalogTenantIsolationTest.php:1331` path. Request changes: correct the test route to `/api/v1/variants/{id}` and add coverage for the remaining fixed reads, or explicitly narrow the claim if those reads are covered elsewhere.

### F2 - Several documented fixed reads lack per-method regression selectors

The production fixes are present, but the test matrix does not cover all documented callsites. For api.catalog.018, `show`, `update`, and `destroy` have selectors at `tests/Feature/Catalog/CatalogTenantIsolationTest.php:1234-1270`, but `duplicate()` at `app/Modules/Catalog/Presentation/Controllers/CompositeItemController.php:144-148` has no cross-tenant selector; `rg -n "duplicate" tests/Feature/Catalog/CatalogTenantIsolationTest.php tests/Feature/Catalog` found only the same-tenant happy path in `tests/Feature/Catalog/CompositeItemCrudTest.php:160-170`. For api.catalog.019, only `RecipeController::show()` is tested at `tests/Feature/Catalog/CatalogTenantIsolationTest.php:1276-1288`; `index()` and `store()` parent reads at `app/Modules/Catalog/Presentation/Controllers/RecipeController.php:35-38` and `app/Modules/Catalog/Presentation/Controllers/RecipeController.php:82-85`, plus `update()`, `activate()`, and `calculateCost()` recipe reads at `app/Modules/Catalog/Presentation/Controllers/RecipeController.php:115-120`, `137-142`, and `166-171`, have no cross-tenant selectors in the `rg -n "recipes/.*/lines|composite-items/.*/recipes|activate|calculate-cost"` probe output except unrelated same-tenant feature tests (`tests/Feature/Catalog/RecipeActivationTest.php:73-124`, `tests/Feature/Catalog/RecipeCostTest.php:159-187`). For api.catalog.020, `store()` is covered at `tests/Feature/Catalog/CatalogTenantIsolationTest.php:1295-1312`, but `update()` and `destroy()` recipe ownership reads at `app/Modules/Catalog/Presentation/Controllers/RecipeLineController.php:81-86` and `132-137` are not covered by a cross-tenant recipe-id selector; `tests/Feature/Catalog/CatalogTenantIsolationTest.php:700-736` covers cross-tenant `component_id` on a same-tenant recipe instead.

Because the output contract asks for per-callsite verification that "the regression test selector exists and asserts what it should," these are not just documentation nits. The current test suite can remain green while regressions in several fixed route-anchored reads go undetected.
