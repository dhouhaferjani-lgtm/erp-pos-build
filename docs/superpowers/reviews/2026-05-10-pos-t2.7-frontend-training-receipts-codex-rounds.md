## Round 1 — APPROVE-WITH-MINOR-EDITS-APPLIED (P1 + P2 + P3 closed)

### P1 — Z-report training inclusion

> When `is_training` is set to 1, offline Z-report generation still selects
> all `offline_receipts` for the shift in `zReportService.ts` and
> `aggregateReportData` counts every row. Any offline training sale made
> before closing a shift would inflate local Z totals and the Z-chain.

**Closure (commit `a3a822b1`):**

- `zReportService::generateZReport`: added `AND is_training = 0` to the
  receipts query so the local Z totals match the server-side
  `Terminal::scopeProduction()` exclusion.
- Bonus filter on `aggregateProductSales` so the "frequently sold"
  projection doesn't pollute analytics with cashier-test purchases.
- New regression test in `zReportService.test.ts` captures the SQL
  string and asserts it contains `is_training = 0`.

### P2 — Voucher mirror divergence on training

> When `isTraining` is true and the payment includes a `store_voucher`,
> the voucher path still resolves vouchers and calls
> `updateVoucherBalanceAndStatus`. The server sync path intentionally does
> not redeem real vouchers for training, so this leaves the local voucher
> mirror decremented without a matching server ledger entry.

**Closure:** skip `collectStoreVoucherPayments` + `resolveLocalVouchers`
when `isTraining=true` (set both to empty array). The voucher tender row is
still preserved in `payments_json` so the server sees the cashier's intent —
it just doesn't create a redemption ledger entry for it. New regression
test asserts `updateVoucherBalanceAndStatus` is not called on training
receipts even when the payments array includes a `store_voucher`.

### P3 — Training receipt-number suffix collision risk

> The 8-hex (32-bit) suffix has ~50% collision probability around 65k
> receipts (birthday paradox), tractable for cumulative training-mode runs
> across decades on the same terminal.

**Closure:** extended suffix from 8 to 16 hex chars (32 → 64 bits).
Collision probability becomes negligible across realistic operational
lifetimes. Existing test regex updated to `[0-9a-f]{16}`.
