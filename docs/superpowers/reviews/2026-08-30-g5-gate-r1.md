# Lane G-5 adversarial gate r1 — opening-stock correction fence (imports + inventory costing)

**Worktree:** `.worktrees/g5-opening` (`feat/g5-opening-correction-fence`, tree UNCOMMITTED)
**Review base:** `70968fbf29fe9abaf554227f678abc8c762b71cf`
**Brief:** `docs/sessions/session-G-imports-hardening-2026-08-29/briefs/LANE-G5-opening-correction-fence-BRIEF.md` (+ r5 patch)
**Method:** static reading, `git diff`, grep, manifest checker only. No PHPUnit/Vitest/PHPStan/deptrac run (memory-constrained machine, per orchestrator instruction). Browser evidence from the orchestrator's 2026-08-30 18:33 run (2/2 pass) is taken as given for the two scenarios it covers.
**Verdict:** **CHANGES**

The core design is sound and largely well executed: the normative order (fence → reverse → reconcile lot → repost → recompute WAC) exists only in `OpeningCorrectionService`, the seam refuses to run outside a caller-owned transaction, `reset()` and the new `reverseAtLocation()` share one extracted body, the correction is journalled as two real documents (reversal `StockMovement` + contra JE, then a fresh `INV-OB-` re-post) rather than a quantity overwrite, the WAC recompute is a quantity-weighted blend at scale 10 written once at scale 6, and the reservation fence takes the larger of the persisted column and the active-reservation sum in both shapes. The lane is not releasable because a chunk-pagination bug can silently drop opening rows in any import over 100 rows, an absent `duplicate_policy` defaults to `override` so a plain products import rewrites posted opening stock and GL without the operator ever choosing it, the fence reads a variant-scoped `stock_levels` row while the reversal writes an unfiltered one, and the rule-22 second-company / re-run proofs are absent.
