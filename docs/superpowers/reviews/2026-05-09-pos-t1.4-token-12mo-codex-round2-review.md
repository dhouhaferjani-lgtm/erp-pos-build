## Findings

### BLOCKERS
None — round-1 P1 closed by `b991aefe`, verified.

### MAJORS

**P2 — Do not grant POS expiry from a spoofable header**
File: `apps/api/app/Modules/Identity/Presentation/Controllers/AuthController.php:71-72` (the `tokenExpiresAt` helper).

Any caller can send `X-Client-Type: pos-tauri` to the public login/register endpoints, so a web back-office user (or scripted client with valid credentials) could bypass the intended 30-day Sanctum lifetime and receive a 12-month token. Since the new Sanctum callback (round-1 fix) makes that row-level expiry override the global TTL, this needed to be gated on a server-side trusted POS/device signal rather than a client-controlled header alone.

**Fix** (`0a15ba7a`):
- Triple-gate: header check + non-empty `device_id` + platform IN (`windows`, `macos`, `linux`).
- Web back-office requests fail every gate (no header, no device_id, no platform). The Tauri client already sends all three (`apps/pos/src/stores/authStore.ts:76-85` + login body at lines 152-157).
- 4 new tests cover each negative branch (no device_id, browser platform, mobile platform) plus a positive smoke for windows/linux.
- Long-term hardening flagged in code comments + the activation hardening plan: replace with a dedicated terminal-pairing flow + cryptographic device handshake.
