## Detailed Write-Up

### 1. MINOR - endpoint-reconciliation TODO describes a backend route that does not exist

The new TODO in `paymentApi.ts` says `/treasury/payment-methods` is a legacy route that is "still mounted" and says to "drop the alias from apps/api/routes/api.php" at `apps/pos/src/api/paymentApi.ts:5-10`.

The actual route grep does not support that. The registered backend endpoints are `/payment-methods` and `/payment-repositories` in `apps/api/app/Modules/Treasury/Presentation/routes.php:27-66`. The `/treasury/payment-methods` string found in the repo is a frontend onboarding path (`apps/api/app/Modules/Tenant/Domain/Enums/OnboardingStep.php:41`), not an API route alias.

That makes the TODO actively misleading for the future go-live owner. Fix the text to identify the real remaining inconsistency, or remove the deferral if the T0.5 endpoint alignment fully closed it.

### 2. MINOR - several TODOs point at missing docs

Step 5.3's anchor-quality contract is about future recoverability: the TODO must point to a concrete PR, kickoff doc, or issue. The Phase 0 TODOs point at `docs/superpowers/plans/2026-04-30-pos-offline-first-hardening.md`, and the cold-start TODO also points at `docs/superpowers/research/2026-04-30-pos-first-launch-offline-activation-research.md`.

Use anchors that a future maintainer can actually open from the repo. The existing T2.2 kickoff doc is present and lists the same Step 5.3 deferrals; issue URLs would be even better.

### 3. MINOR - T1.0 CSV-driven product import deferral was missed

The T1.0 kickoff's explicit deferral list has three items: bulk insert, shared SCALE base class, and CSV-driven product import. This sweep adds the first two at `apps/api/database/seeders/ParapharmacySeeder.php:324-333`, but does not capture CSV-driven import.

This is a small documentation gap, not a runtime issue. Add a third TODO near `seedProducts` / product generation, or make the PR body explain why CSV-driven product import is intentionally not a go-live follow-up.
