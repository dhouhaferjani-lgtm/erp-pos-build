## 4. Claim 3 (their open question) — `api.get` vs `apiGet`: ADJUDICATED, keep `api.get`

**Their choice is correct; no change.**

- `apiGet` (`lib/api.ts:225-228`) returns `response.data.data` — it structurally discards `meta`.
- This endpoint's `meta` is load-bearing: `CashMovementsMeta` (`useCashMovementsReport.ts:33-35`)
  carries the offset pagination **and** `totals: Record<currency, {in,out,net}>`, consumed at
  `CashMovementsReportPage.tsx:68-72, 261-292, 316-328`. `apiGet` would silently blank the totals
  panel and the pager.
- `docs/conventions/01-API-RESPONSES.md` (List row: `{ data: [], meta: {...}, links: {} }`) plus
  CLAUDE.md rule 14's note ("for paginated `{data,meta}` endpoints use `api.get` + return
  `response.data`") both endorse this exact shape.
- **No double-unwrap:** `useCashMovementsReport.ts:67-71` unwraps the axios envelope once
  (`response.data` = the JSON body `{data, meta}`) and returns it; the page then reads
  `.data` / `.meta` off the report object. Correct single unwrap.
- The reason is documented in the hook docblock (`:49-51`), which is the right place for it.

## 6. Claim 5 — the MTP-MLC-08 flip

**Untouched hunks: VERIFIED.** The branch diff of `w7-multilocation.spec.ts` is exactly two hunks,

**Typecheck: VERIFIED** (`tsc --noEmit --strict` standalone; `pnpm typecheck` only includes `src`,
so `e2e/**` is NOT covered by the project gate — worth knowing).

**MAJOR-2 — the flipped assertions compare PAGE 1 payloads as if they were complete SETS.**
`read()` (`w7-multilocation.spec.ts:499-503`) sends no `per_page`, and the endpoint defaults to
**50** (`GetCashMovementsRequest.php:77-82`) ordered `date DESC` (`CashMovementsReportService.php:151-156`).
On any tenant with >50 cash movements:
- the subset assertion (`:554-558`) breaks for a **correct** implementation — a single branch's 50
  most recent rows reach further back in time than the global 50, so scoped rows legitimately
  absent from unscoped page 1 are reported as a scoping defect (false RED);
- the Σ assertion (`:596-601`) sums up to 150 scoped rows against 50 unscoped rows, so
  `branchTotal` will routinely exceed `total(allBefore)` and fail (false RED).
**Fix directive:** either request `per_page=200` on every read *and* assert `meta.last_page === 1`
so the "set" premise is proven, or — better — drive the money/count halves off the payload's own
`meta.totals` / `meta.total`, which the service computes over the FULL filtered set
(`CashMovementsReportService.php:118-150`) and are page-independent.

**MAJOR-3 — the flip is vacuously GREEN if the fix over-filters to nothing.** With
`scopedTunis1 = scopedTunis2 = scopedWarehouse = []`: subset → `[]` passes (`:554-558`); disjoint →
`[]` passes (`:570-574`); `.every(...)` → `false` passes (`:581-586`); `headroom` → positive,
passes (`:597-601`); the UI check only asserts "no NaN" (`:607-609`). The old tripwire at least
pinned equality; the flip loses the ability to distinguish "correctly scoped" from "returns
nothing" — exactly the regression the journal-lines leg can produce (`whereExists` on
`payment_repositories.location_id`, `CashMovementsReportService.php:334-336`, silently drops every
repository whose `location_id` is NULL).
**Fix directive:** assert non-emptiness for the shop scopes the fixture guarantees POS cash for,
e.g. `expect(scopedTunis1.length, 'the Tunis-Lac scope is not merely over-filtered to nothing').toBeGreaterThan(0)`,
and/or assert `Σ meta.total over the three scopes > 0`.

**Nothing weakened otherwise.** The subset + pairwise-disjoint pair is strictly stronger evidence
than the three equality tripwires it replaces, and the deliberate downgrade of the plan's
"Σ == All" to "Σ ≤ All" is honestly justified in-comment (`:536-546`) and in the ticket
(residual 2) by the NULL-location company-cash case, which
`reportLocationScope()`/`isUnrestricted` genuinely creates.

**Evidence gap (not a finding, a request):** Playwright cannot be run from this gate (needs a live
stack + the W-7 fixture tenant). The claim "MTP-MLC-08 is green" is **unverified here** — attach
the run log, ideally against a tenant with >50 cash movements so MAJOR-2 is actually exercised.
