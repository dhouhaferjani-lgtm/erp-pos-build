## Closing rationale

The spec has the right high-level instinct: do not mutate signed bytes, use versioned successors, and keep the device as the canonical author. However, the actual codebase has more signed and projected `unit_price` surfaces than the spec admits, and the current registry/parser design cannot accept v1 and v2 by merely changing a mapping. The migration plan also uses stale column scales, which would violate the precision contract. Fix those before turning this into an implementation plan.
