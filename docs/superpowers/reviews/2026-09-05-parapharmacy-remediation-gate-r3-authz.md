## 2. NEW findings

### BLOCKER

#### B-r3-1 — The terminal-scoped tender-config projection is designed to bypass the location scoping W1 introduces, but no terminal-identity authority exists at HEAD and the spec never says how the server establishes one. CONFIRMED.

Spec 143: "distribute W2 tender bindings through a terminal-scoped tender-config projection … **Terminal identity/config entitlement supplies its allowed destinations independently of the current cashier's balance-view scope**"; 145 makes this projection a **prerequisite** to scoping `/payment-repositories`; 188 grounds the unsealed D8 branch in "the terminal trust model".

CONFIRMED current state:
- There is **no terminal credential and no terminal-authenticating middleware**. Nothing under `apps/api/app/Http/Middleware/` or `app/Modules/*/Presentation/Middleware/` authenticates a terminal; the only client marker in the codebase is the self-asserted header `X-Client-Type` (`app/Modules/Identity/Presentation/Controllers/AuthController.php:60`, `app/Modules/POS/Presentation/Middleware/EnsureWebPosDemoTenant.php:33`).
- Terminal identity over HTTP is a **caller-supplied UUID** validated only for tenant+company: `app/Modules/POS/Presentation/Requests/ClaimTerminalRequest.php:33-40` (`ScopedExists::tenantAndCompany('pos_terminals', …)`); the same tenant+company-only pattern recurs in `VoucherLedgerSyncRequest.php:52-57`, `HoldOrderRequest.php:30`, `StoreReturnRequest.php:48`.
- The **precedent the spec would be built on is company-wide and ungated**: `app/Modules/POS/Presentation/Controllers/PosPaymentPolicyController.php:13-20` — "policy for the authenticated terminal's company … Same posture as the fraud-settings endpoint: sanctum + CompanyContext, **no extra gate, no new permission**" — `show()` at `:29-33` resolves nothing but `requireCompanyId()`. Route `app/Modules/POS/routes.php:266`.
- No "terminal trust model" is documented anywhere in `docs/` (grep for `terminal trust` returns only unrelated CI/enforcement text).

Failure scenario: the implementer follows the only precedent and ships `GET /pos/tender-config` (or a `terminal_id`-parameterised variant) as sanctum + company scope. A restricted branch-A cashier then (a) reads branch-B's destination bindings — repository IDs, types and display labels for every branch of the company, which is precisely the destination-catalogue exposure W1's own text forbids ("Company-global bank identifiers/balances must not leak through destination pickers; expose only permitted destination names/IDs", 131), and (b) because W1 states the projection is authority **independently of the cashier's scope**, the device can bind an A-authored tender leg to B's drawer, producing cross-branch custody misattribution on sealed money — the exact class W1 exists to close. The location scoping is defeated through its own declared prerequisite, and the spec has no acceptance row that would catch it (137 tests supervisor→cashier and terminal/company *changes*, never "operator asks for another branch's terminal").

Minimum correction (spec, ~3 sentences + 1 acceptance row):
1. State the HEAD truth: a POS device authenticates as a **user** (sanctum token); there is no terminal credential, and `terminal_id` is caller-supplied and validated only for tenant+company (`ClaimTerminalRequest.php:33-40`). Delete or define "the terminal trust model" (188) — it is currently an appeal to a mechanism that does not exist.
2. Specify the server-side rule for the projection: the terminal is derived from the caller's **claimed/active** terminal binding (`pos_terminals.hardware_identifier` claim, `TerminalController::claim`), not from a free-form request parameter; allowed destinations are filtered by **that terminal's location**; a request naming a terminal the caller is not operating is denied (scoped-not-found), and cross-company/cross-tenant terminal ids 404 as they do today.
3. Add the acceptance row: "restricted branch-A operator requesting branch-B's terminal tender config is denied and receives no B destination IDs/labels; a foreign-tenant terminal id 404s; the projection never returns a destination outside the terminal's own location."

Spec 256: "Unknown entitlement is visible blocked lot work, not guessed enabled/disabled"; 256 also: "Unentitled tuples may be reported as a separate non-alerting 'not entitled' cohort"; matrix row L6 (369) repeats the non-alerting cohort.
