Verdict: closed. The requested race guard is present and covered.

## 3. Ricochet Findings

### 3. NIT - NaN guard is closed, but keep the explicit test

Corrupted metadata is handled correctly. `terminalStore.ts:173-179` converts `raw` with `Number(raw)`, requires `Number.isFinite(parsed)`, and skips `setLastSyncAt` for non-finite values. The test at `apps/pos/src/stores/__tests__/terminalStore.preWarm.test.ts:198-206` covers `not-a-number` and asserts no write.

This is not blocking. Keep the test because it protects a real local-storage/SQLite corruption edge.

### 4. MINOR - Stale scheduler timing comments remain

The race is fixed for `lastSyncAt`, but the pending-count hydration comment still says the first tick is "debounced by ~1 s" and implies a race is unlikely at `apps/pos/src/stores/terminalStore.ts:134-140`. The code still starts the scheduler before pending-count hydration at `apps/pos/src/stores/terminalStore.ts:110-146`.

This is not a functional blocker for T1.3 because pending count is sourced from SQLite truth, and the `lastSyncAt` race has the new guard. It is still misleading documentation near concurrency-sensitive code.

Recommended follow-up: update the comment to say `scheduler.start()` may begin a tick before hydration settles, and that pending count tolerates last-writer-wins because both writers source SQLite.

### 5. MINOR - Test cleanup is close but not fully failure-safe

The pre-warm store mock now resets the mutable `syncStoreMockState.lastSyncAt` in `beforeEach` at `apps/pos/src/stores/__tests__/terminalStore.preWarm.test.ts:90-103`, so the MAJOR-2 regression tests do not leak the mocked in-memory timestamp across cases.

The remaining cleanup gap is in `SyncButton.test.tsx`: the debounce test enables fake timers at `apps/pos/src/components/atoms/SyncButton/__tests__/SyncButton.test.tsx:134-150` and restores real timers only at the end of the test. If an assertion throws before line 150, fake timers can leak into later tests in the same file/process.

Recommended follow-up: add `vi.useRealTimers()` to the file-level `beforeEach`/`afterEach`, or wrap the fake-timer test in `try/finally`.

### 6. NIT - The nested dot aria-label is now redundant

The button's explicit `aria-label` is now the source of truth at `apps/pos/src/components/atoms/SyncButton/SyncButton.tsx:56-68`. The amber dot still carries its own `aria-label` at `apps/pos/src/components/atoms/SyncButton/SyncButton.tsx:73-79`.

This does not appear to create a blocking double-announcement issue for the focused button, because the button's accessible name comes from `aria-label` rather than descendant text. Still, the child label is now redundant and can confuse future tests into treating the dot as the accessibility contract again.

Recommended follow-up: keep `title={t('sync.degradedTitle')}` for mouse tooltip, and consider `aria-hidden="true"` on the dot once the button label test remains the primary assertion.
