### Why `''` is normalised to `'0'` at the wire boundary only
`lines.*.unit_price` is `required|numeric` server-side and the **draft autosave fires at keystroke
frequency** (`DocumentForm.tsx:331-350`), so leaving `''` in the payload would turn an unpriced line
into a stream of 422s and trip the autosave-failed / beforeunload guard. `''` is therefore a UI
state only: the operator sees a blank field, an unsaved-yet-drafted line is visibly worth nothing
(the honest state), and it can never become the retail price.

## C2 — a zero-priced purchase order no longer confirms, and no longer reloads as if priced

**Server (the durable half).** `PurchaseOrderService::confirm()` refuses any non-bonus line at
`unit_price` 0 with `UnpricedPurchaseOrderLineException` → typed **422 `PO_LINE_UNPRICED`**,
operator text in **en/fr/ar**. It is a `\RuntimeException`, caught BEFORE `\DomainException`,
because this controller maps every `\DomainException` to `INVALID_STATUS_TRANSITION` and an
unpriced line is not a status-transition error — the N-2 precedent, and a test pins it.

*Free of charge*: `document_lines.is_bonus_line` is the product's explicit zero-value flag
(migration `2026_07_02_100000`: "Marks explicit zero-value supplier invoice / credit-note bonus
lines") and is the one exemption — a test confirms such a PO successfully. The **other** bonus
mechanism, same-product purchase bonuses, rides `free_quantity` on a normally PRICED line and never
reaches the refusal. So: yes, an explicit free-of-charge flag exists; 0 is refused for every other
purchase line.

The comparison uses `bccomp` at the **document currency's** scale via the injected
`CurrencyScaleResolverInterface` (`getScaleSafe($currency, 3)` — confirm also runs from
console/queued contexts with no `CompanyContext`), never a hardcoded literal: PHPStan's
`ForbidHardcodedBcmathScale` caught the first draft and it was fixed, not baselined.
`tests/Unit/Document/PurchaseOrderServiceTest.php` constructs the service by hand and was updated
for the new dependency (rule 13 unchanged — still constructor injection).

**Client.** `hydrateLineUnitPrice` loads a persisted zero on a PURCHASE document as blank, so a
reopened autosave draft is shown blank and flagged rather than displaying `0.000` as if the
operator had typed it. Scoped to purchase documents to match the server guard; a sales line loads
untouched (covered by its own test) because 0 is accepted there.
