## Answers to the seven attack questions

**(a) Trigger seam.** Dispatchable, but not "reusable" as-is. Needs: `productId` (available per row as `import_rows.imported_entity_id`, `ImportService.php:576`), `expectedPlatformProductId` (from the phase's own lookup), `barcode`, and `vertical` from `Vertical::platformVertical()` (`Vertical.php:153-165`, null for retail). The seam itself is six inline controller lines (`ProductController.php:565-575`) — extraction is mandatory, not optional (K7-S1-07). Company scoping trap: the job re-reads `Product::find($id)` with **no** tenant/company predicate (`ApplyCatalogEnrichmentJob.php:46`), relying on the tenant DB binding (K7-S1-15); and the backlink write from the phase must be company-scoped because a tenant may have several companies with the same barcode. No variant trap found — enrichment applies to `products` rows only. Positive note: `applyCatalogHit` is already idempotent (`CatalogEnrichmentService.php:41-50` guards on an existing accepted `catalog` `EnrichmentResult`) and never overwrites name/barcode (`:52-57`), so re-application cannot clobber operator edits.

**(b) Phase design.** Phases are `finalizeImport()` match arms (`ImportService.php:758-765`) and run inline in BOTH paths; the sync/async split is `ASYNC_THRESHOLD = 100` at `ImportController.php:48,682`. A `finalizeImport` arm is therefore the WRONG slot (K7-S1-02). A queued job gets tenant/database context (`BindsTenantContext`) but **no `CompanyContext`** — and the platform client makes one mandatory (K7-S1-01). This is the single highest-risk item in the lane.

**(c) BarcodeLookupService.** Cache prefix confirmed `platform:lookup:v2:` + `{vertical}:{barcode}`, TTL 3600 s, no tenant in the key (`:21-23,49`). Error semantics: `lookup()` never throws — it returns typed error reasons, so "not-found → warning, unavailable → warning" is compatible **provided** the phase calls `lookup()` and not `lookupCatalogProduct()`, which converts `platform_unavailable`/`platform_error` into a thrown `PlatformCatalogUnavailableException` (`:143-148`) for queue retry. The brief must name which method it calls. Per-row synchronous HTTP at 5000 rows is NOT acceptable inline (K7-S1-02) and the cap design does not hold as written (K7-S1-11); the circuit breaker (`:58`, threshold in `PlatformHttpClient`) is the real backstop and must be honoured by stopping the run.

**(d) Push gate.** **Verified safe.** `push_enabled` is consulted in exactly four places (`ProductSubmissionService.php:291`, `SendEnrichmentFeedbackJob.php:54`, `SendBrandMappingJob.php:47`, `PurchaseHubService.php:81`) plus the config line. `BarcodeLookupService` and `PlatformHttpClient::buildRequest()` do **not** consult it — the lookup works with `SYNERIVA_PLATFORM_PUSH_ENABLED=false`. One second-order note: `withLocalBrand()` calls `brandResolution->dispatchPushIfNeeded()` (`BarcodeLookupService.php:126`), which reaches `SendBrandMappingJob.php:47` — correctly no-ops under the gate. F-IMG-3 callers/handlers that would break are enumerated in K7-S1-08 (`ProductSubmissionCorrelationTest.php:297`, `PhotoUploadUrlController.php:39`, `EnrichmentRefreshController.php:45` + `ProductForm.tsx:675-679`, and the silent-swallow + false success toast at `ProductForm.tsx:594-624`). Note the FE has **no** code keyed on `platform_unavailable` anywhere (`apps/web` grep clean), so the FE change is additive.

**(e) Idempotency + rule 22.** Re-run skip on "already linked" is sound and is double-protected by `CatalogEnrichmentService.php:41-50`; but note `ApplyCatalogEnrichmentJob:62` CLEARS the backlink on a genuine miss, so a previously-missed row re-looks-up on every re-run (cache-absorbed for 1 h). Second-company proof is mis-stated (K7-S1-03). Second-location is irrelevant to enrichment itself but is a rule-22 requirement on any products-import change — the brief must say which of the two it claims. Warning-code enum/i18n/docs/manifest collisions with G-2/G-5/K-6 are K7-S1-04 and K7-S1-09.

**(f) Playwright.** See K7-S1-12 — the SSRF guard blocks localhost, `::1`, all private/reserved/CGNAT/multicast resolved IPs, non-https schemes and non-443 ports; the lookup transport is unguarded and stubbable locally.

**(g) Toggle visibility.** Brief wording is wrong — the key is env-level (`config/services.php:106`). Corrected predicate in K7-S1-10.
