## 2. The decision the brief asked for: CREATE-on-miss (not warn-only)

Ruled **create-on-miss + per-row report**, from the existing brand behaviour and the
scoping rules. Evidence, with file:line:

1. **The sibling block already creates.** `ProductService.php:91-95` resolves `brand` through
   `BrandResolutionService::resolve()`, which ends in `Brand::create([...])`
   (`BrandResolutionService.php:85-92`). The same import created brands and discarded
   categories — an asymmetry with no stated policy behind it.
2. **Categories are COMPANY-scoped only — never vertical-scoped.** The table carries
   `company_id`, `parent_id`, `slug` and a unique `(company_id, slug)`; there is no vertical
   column (`database/migrations/tenant/2025_12_26_194624_create_categories_table.php:14-16,38`).
   `config/verticals.php` declares **no** category scoping — its only `Parapharmacy` block
   (`:331-356`) lists modules and a `requires_batch_tracking` default, nothing about
   `categories`. So a created row cannot land in the wrong vertical: `company_id` fully
   determines its scope.
3. **The vertical-gated "Parapharmacy → Product Category" of N-13 is a DIFFERENT field** and is
   deliberately untouched: it is `ParapharmacyProductMetadata.category`, a
   `ParapharmacyCategory` **enum** (`Product/Application/DTOs/ParapharmacyProductMetadataData.php:42`)
   behind `module:Parapharmacy` (`Product/routes.php:86-89`) — not a `categories` row. Nothing
   this lane does can satisfy it; the report's "the import cannot populate that field" stands,
   and stays with the N-13 lane (see §6).
4. **There is no other way in.** `category_name` is a **products** column
   (`Import/Domain/Enums/ImportType.php:125`) and no `categories` ImportType exists
   (`ImportType.php:9-43`), so a day-one tenant has no route to create categories before the
   products import. `docs/modules/imports.md` calls Categories a Level-1 foundation dependency
   but ships no importer for it — warn-only would leave the operator with a warning and no
   remedy, which is exactly the trap N-2's pre-delivery guard fell into.

**"Never silent" is honoured on both halves.** Auto-creating master data from a free-text
spreadsheet cell is itself a state change worth reporting (a typo'd `Hygène` becomes a real
category), so every create is reported per row and nothing is invisible:
- `_results['category']` = `matched` | `created` | `restored` (`ImportService.php`, importProduct).
- A non-blocking row warning `category_created` / `category_restored` with the offending name,
  which flows into the **`warnings` column of the result workbook**
  (`ResultWorkbookService.php:61,74,112-124`) and into `warning_rows`
  (`ImportController.php:672,681-691`). A **match** stays silent — no new noise on re-imports.

## 5. Correctness details a reviewer should poke at

- **Idempotent.** Re-import matches on exact name, then on slug. Test 2 runs the *same file
  twice* and asserts `Category::count() === 1` and `_results['category'] === 'matched'` on both
  passes.
- **Slug variants cannot collide.** `Hygiene` and `hygiene` both slug to `hygiene`, and the
  unique index is `(company_id, slug)` — matching on slug is what stops the second spelling from
  raising a unique violation instead of linking. Covered by row 2 of test 2.
- **Race + soft-delete.** `Category` uses `SoftDeletes` and the unique index is NOT partial, so a
  trashed row still holds its slug. `Category::create()` is wrapped: on `QueryException` the
  holder is re-fetched `withTrashed()`; a trashed holder is `restore()`d and reported as
  `restored`, a live holder is reported as `matched`, and if there is no holder the exception is
  re-thrown unchanged (never swallowed). This also covers two queue workers racing the same name.
- **Non-latin names.** `Str::slug('...')` returns `''` for pure Arabic/CJK/punctuation names,
  which would make every such category collide on `(company_id, '')`. Falls back to
  `'category-'.substr(hash('sha256',$name),0,16)` — deterministic, so re-imports still match.
- **Blank/whitespace-only values are ignored**, as before (`trim(...) !== ''`).
- **Money/quantity:** none touched. No float anywhere in this lane (rule 19 n/a).
- **Migration: NO.** No schema change, no DDL, no backfill. Nothing to census, no fleet-abort risk.
