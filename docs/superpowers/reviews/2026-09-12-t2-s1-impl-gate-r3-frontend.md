## Round-3 findings

### MINOR

**m1 — The confirm copy tells the operator to "use Close", an affordance that does not exist anywhere in the web UI at this tip.** `apps/web/src/locales/en/stock-transfers.json:151` ("… use Close to write off or return a short shipment") and `locales/fr/stock-transfers.json:151` ("… utilisez Clôturer pour perte ou retour"), rendered at `pages/StockTransferDetailPage.tsx:277-281`. Repo-wide grep over `apps/web/src` for a close route, endpoint, button or i18n action key → **zero hits**; the checklist itself states the path is API-only until S4 (`PROMOTION-CHECKLIST-2026-09-09-t2t3.md:16`: "a short shipment is closed via `POST /close`"). A web-only operator reading this sentence has no way to act on it — the owner rule is that a control the user cannot reach is hidden, not advertised. The wording came from my own r2 F-4 directive, so this is a disclosure of its consequence, not a re-litigation. *Fix directive:* drop the trailing "; use Close…" clause (both locales) until S4 lands the Close affordance, or reword it to name the actor rather than the button ("a supervisor must close the shortage"), keeping the `.inTransitDescription` branch untouched.

**m2 — The short-line predicate hardcodes the storage scale as the string literal `'0.0000'` while the codebase already owns a scale-agnostic decimal comparator.** `pages/StockTransferDetailPage.tsx:279` `line.quantity_remaining !== '0.0000'`. It is **correct today** (proof in the F-4 row: `bcsub(..., QuantityScale::SCALE)` with `SCALE = 4`), but it silently mis-reports every line as short if the emitted representation ever changes (a DTO that formats to the unit's `decimal_places`, a trailing-zero-trimming serializer, or a scale change) — and the failure mode is a wrong sentence in a confirmation dialog, invisible to lint, typecheck and the current tests. `bccomp` (`src/lib/decimal.ts:115`, big.js-backed, no float) and `QUANTITY_STORAGE_SCALE` (`src/lib/quantityScale.ts:5`) already exist for exactly this. *Fix directive:* replace with `bccomp(line.quantity_remaining, '0') !== 0`; no arithmetic, no float, same result, scale-independent.

**m3 — The new confirm copy has no plural handling in either locale, so the singular case reads ungrammatically.** `locales/en/stock-transfers.json:151` renders "1 of 2 lines **have** not fully arrived"; `locales/fr/stock-transfers.json:151` renders "1 **lignes** sur 2". i18next plural resolution is available and used elsewhere in the app's bundles. *Fix directive:* switch the interpolation to `count` and add `_one`/`_other` (fr `_one`/`_many`/`_other`) variants, and update the exact-string assertion at `__tests__/StockTransferDetailPage.test.tsx:97`.

**m4 — `StockTransferType` is now a dead export that duplicates a generated enum.** `features/stock-transfers/types/index.ts:4`. Repo-wide grep for `StockTransferType` across `apps/web/src` returns **exactly one hit — its own declaration**; the field it once typed now comes from `StockTransferData.transfer_type` (`generated.d.ts:1215`) which points at `App.Modules.Inventory.Domain.Enums.TransferType` (`:1454`). The sibling duplicate `TransferCostDistribution` `:6-9` is still consumed by `pages/CreateStockTransferPage.tsx`. §0AB ruled both → S4; the new fact is that the first one is now unreferenced, so deleting it costs nothing. *Fix directive:* S4 deletes `:4` outright and aliases `:6-9` to `App.Modules.Inventory.Domain.Enums.TransferCostDistribution`.

**m5 — The Complete/Cancel affordances carry no FE permission check, and this slice widened when Complete appears.** `pages/StockTransferDetailPage.tsx:38-39,98-119`; the feature contains **zero** `hasPermission`/`usePermissions` references (grep over `src/features/stock-transfers/`), while the closest sibling gates identically-shaped actions — `features/stock-adjustments/pages/StockAdjustmentDetailPage.tsx:80-81` `status === 'draft' && hasPermission('inventory.adjustments.post')`. The route guard only requires `inventory.transfers.view` (`src/routes/index.tsx:1405,1415,1425`), so a view-only actor sees a primary Complete button and takes a backend 403. This **fails closed** (the API enforces `inventory.transfers.complete`), so it is a UX/one-main-element defect, not a security hole, and the `in_transit` half is pre-existing — but `:38` is a line this slice owns, and the new `partially_received` state extends the exposure. *Fix directive:* S4 (with F-11's `hasModule('Inventory')` work) gates `canComplete` with `hasPermission('inventory.transfers.complete')` and `canCancel` with `hasPermission('inventory.transfers.cancel')`; add a line to the checklist's S1 disclosures if it is not fixed in this lane.
