## Verdicts on the implementer's three open questions

### Q1 — `lib/format.ts` importing `useCompanyStore`: acceptable, or require `setDefaultCurrency()` / explicit-currency?

**KEEP the store read. Reject `setDefaultCurrency()`. Harden it (I5) and rewrite the doc comment.**

- **Do not adopt `setDefaultCurrency()`.** A module-level mutable default is strictly worse than the store read: it is
  order-dependent (whoever calls it last wins), invisible at the call site, silently stale in tests that never call
  it, and it creates a *second* source of truth for "the active company's currency" — which is the defect class L4
  exists to remove.
- **The store read is defensible here.** SSR is irrelevant (Vite SPA). `getState()` is zustand's documented
  non-React escape hatch. And the tenant-scoped-key rule's spirit *supports* it: that rule says ambient tenant
  identity is legitimate but must be made explicit at the boundary — which is exactly the shape here (explicit
  `currency` at every call site; the store only as last resort).
- **The real objection is not testability — it is REACTIVITY.** `getState()` does not subscribe, so a component that
  relies on the default will **not re-render when the user switches company**. Today that bug is unreachable: I
  enumerated every `lib/format.formatCurrency` caller in `src/` and **all of them pass an explicit currency**. But the
  comment the lane wrote at `format.ts:17-31` actively *invites* call sites to omit it ("degrades to the company's
  currency rather than to euros"), which is how the latent bug becomes a live one.
- **Conditions:** (a) apply the defensive read in I5; (b) rewrite `format.ts:17-31` so it does **not** invite omission —
  state plainly that the default is a fallback of last resort, is **not reactive to a company switch**, and that the
  entity's currency must be passed at every call site. Keep `FALLBACK_CURRENCY = 'EUR'` and note it matches
  `useCurrency.ts:47` so the two fallbacks cannot drift.
- On testability: six partial mocks is a real cost, but the correct response is the faithful-stub fix the lane already
  made plus the defensive read — not a weaker architecture.

### Q2 — FinanceWidget belt-and-braces (`useCurrency().format` AND the contract default): keep or simplify?

**KEEP BOTH — but stop calling it belt-and-braces, because they are not redundant.**

They close different tickets on different surfaces:
- `useCurrency().format` in the component closes **D6** and is the *only* one of the two that is **reactive** — it
  subscribes via `useCompanyStore((s) => s.getCurrentCompany)`, so the tiles re-render on a company switch. Dropping it
  in favour of the bare default would reintroduce a stale-render bug on every company switch.
- The `activeCurrency()` default in `lib/format` closes the **F-7 family contract** for every *future* caller. Dropping
  it means the next no-option call renders euros — D6 verbatim.

Neither is dead weight. **However**, the justification recorded in the code ("the way that sibling does",
`FinanceWidget.tsx:12-15`) is **not accurate** — the sibling resolves its locale from `company.locale`, the widget from
the currency (I1). Correct that claim or unify the two, but do not simplify away either half.

### Q3 — `PriceInputWithMargin` partial-mock fix vs defensive `activeCurrency()`: lane problem or ticket?

**Both, and it is a LANE problem — do not defer it.**

- The mock fix (`PriceInputWithMargin.test.tsx:44-60`) is the *right* shape and should stay: a stub that omits a method
  the production store exposes is a lying test double, and the lane's comment says so correctly.
- But the lane **created** the coupling that makes partial `companyStore` stubs fatal, and left four more of them in the
  repo (I5). Shipping a change that arms four latent `TypeError`s and calling it someone else's ticket is not
  acceptable at a merge gate — especially when the mitigation is one line of optional chaining with zero behavioural
  change against a real store.
- **Ruling:** apply the defensive `activeCurrency()` **in this lane** (I5); keep the faithful stub; file a P3 ticket for
  the remaining four partial mocks to be made faithful (defensive code prevents the crash, it does not make the stubs
  honest). The defensive read must return the *same* `FALLBACK_CURRENCY` as the genuine no-company case — no third
  behaviour.

### R2-a (MUST-FIX, docs-only, no re-gate) — the R2-1 exemption is **not yet** scoped tightly enough

Two sentences can be read as licensing `number_format` on money in new code:
