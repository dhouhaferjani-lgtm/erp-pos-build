## Summary

## Regressions from v1 (NEW issues introduced by the v2 edits)

### BLOCKER: A6/A7 can deadlock while trying to close the denominator race

The new public `recordCostEvent()` locks the target transfer before it delegates to WAC (`docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:736`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:737`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:825`). The new WAC method then locks the product and tries to `lockForUpdate()` the joined in-transit transfer rows (`docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:627`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:630`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:643`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:655`).

Existing `complete()` locks its own transfer before it locks the product and receives destination stock, and v2 only says to remove capitalization from `complete()`, not to change that lock order (`apps/api/app/Modules/Inventory/Application/Services/StockTransferService.php:157`, `apps/api/app/Modules/Inventory/Application/Services/StockTransferService.php:160`, `apps/api/app/Modules/Inventory/Application/Services/StockTransferService.php:168`, `apps/api/app/Modules/Inventory/Application/Services/StockTransferService.php:172`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:917`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:919`).

Two-process deadlock:

- Process B records a cost event on transfer A. It locks transfer A, then locks product P in WAC (`docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:736`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:737`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:627`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:630`).
- Process C completes transfer C for product P. It locks transfer C first, then blocks waiting for product P (`apps/api/app/Modules/Inventory/Application/Services/StockTransferService.php:160`, `apps/api/app/Modules/Inventory/Application/Services/StockTransferService.php:168`, `apps/api/app/Modules/Inventory/Application/Services/StockTransferService.php:172`).
- Process B's in-transit joined query now tries to lock matched `stock_transfers` rows, including transfer C; B waits for C while C waits for B's product lock (`docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:643`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:647`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:649`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:655`).

The fix should not lock every in-transit transfer row after taking the product lock. Once every transfer state transition for P must take the product lock before changing stock/status, WAC can lock product P, read stock-level rows, read in-transit rows without taking parent transfer row locks, and still see a consistent denominator (`apps/api/app/Modules/Inventory/Application/Services/StockTransferService.php:168`, `apps/api/app/Modules/Inventory/Application/Services/StockTransferService.php:172`, `apps/api/app/Modules/Inventory/Application/Services/StockTransferService.php:304`, `apps/api/app/Modules/Inventory/Application/Services/StockTransferService.php:308`).

### BLOCKER: A6's row-lock claims are built on aggregate `sum()` queries

A6 says it lock-and-sums `stock_levels` and joined `stock_transfer_lines` (`docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:633`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:641`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:643`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:656`). Laravel's `sum()` calls `aggregate()`, `aggregate()` executes a `get()`, the grammar includes `aggregate` and `lock` components, and PostgreSQL grammar emits bare `for update` (`apps/api/vendor/laravel/framework/src/Illuminate/Database/Query/Builder.php:3963`, `apps/api/vendor/laravel/framework/src/Illuminate/Database/Query/Builder.php:3965`, `apps/api/vendor/laravel/framework/src/Illuminate/Database/Query/Builder.php:3999`, `apps/api/vendor/laravel/framework/src/Illuminate/Database/Query/Builder.php:4003`, `apps/api/vendor/laravel/framework/src/Illuminate/Database/Query/Builder.php:4004`, `apps/api/vendor/laravel/framework/src/Illuminate/Database/Query/Grammars/Grammar.php:38`, `apps/api/vendor/laravel/framework/src/Illuminate/Database/Query/Grammars/Grammar.php:50`, `apps/api/vendor/laravel/framework/src/Illuminate/Database/Query/Grammars/PostgresGrammar.php:355`, `apps/api/vendor/laravel/framework/src/Illuminate/Database/Query/Grammars/PostgresGrammar.php:358`).

The plan target is PostgreSQL 16+ (`docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:9`). A plan that relies on row locks for a financial correctness fix should select and lock rows, then sum in PHP or in a separate aggregate after the rows are locked; the current A6 snippet does not specify that shape (`docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:636`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:641`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:649`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:656`).

### BLOCKER: F3's negative reversals are skipped by the WAC loop

A1 intentionally permits signed amounts, and F3 asks cancel to emit `amount = -(prior event amount)` (`docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:170`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:176`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:2120`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:2165`). A7's capitalization loop converts the event to a float, computes each allocated share, and then `continue`s when `$allocated <= 0` before line cost and WAC adjustment (`docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:804`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:812`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:815`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:817`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:825`).

With the F3 example of `+100.0000` then `-100.0000`, the second event row can be inserted, but no product WAC is adjusted and no line allocation is reduced because every allocated share is negative and hits that guard (`docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:2134`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:2138`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:2152`, `docs/superpowers/plans/2026-05-28-inventory-transfer-remediation.md:2159`).
