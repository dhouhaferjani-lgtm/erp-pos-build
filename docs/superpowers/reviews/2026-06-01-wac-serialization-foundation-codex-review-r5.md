### C. Guard Test

The guard checks each listed multi-product seam caller by extracting the method body, finding `costLock->acquire(` at `apps/api/tests/Architecture/InventoryCostLockCoverageTest.php:116-123`, then comparing it to the last `foreach` position in that body at `apps/api/tests/Architecture/InventoryCostLockCoverageTest.php:138-148`. In other words: when the seam loop is visibly in the same method body, the heuristic requires the up-front acquire to appear before the last loop.

Blind spots remain. First, a method whose seam loop is not the last `foreach` can be misclassified because the test treats the last `foreach` as the seam loop. Second, a method can extract the seam loop to a private helper so the public method body has no `foreach` at all; in that case the test only proves an acquire call exists, not that the helper is invoked inside the acquire closure. Despite those blind spots, the test still provides meaningful regression value: it pins the known multi-product caller list at `apps/api/tests/Architecture/InventoryCostLockCoverageTest.php:102-111`, catches a missing up-front acquire, and catches the exact `postBatch()` style regression where a visible loop accumulates advisory locks in row order. I do not require a stronger assertion for this commit because manual review confirmed the helper calls are inside the acquire closures at `apps/api/app/Modules/Inventory/Application/Services/StockTransferService.php:186-187`, `apps/api/app/Modules/Inventory/Application/Services/GoodsReceiptService.php:78-84`, and `apps/api/app/Modules/Document/Domain/Services/ReturnNoteService.php:92-94`.
