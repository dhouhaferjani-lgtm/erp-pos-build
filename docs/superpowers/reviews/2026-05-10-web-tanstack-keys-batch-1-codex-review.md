## Findings

[F1] Prefix invalidations are not real prefixes of the tenant-scoped leaf query keys, so several mutation cascades do not invalidate the caches they claim to target. `tenantScopedKey` appends the active tenant and company to the end of the supplied segments (`apps/web/src/lib/tenantScopedKey.ts:29`, `apps/web/src/lib/tenantScopedKey.ts:34`). The list hook therefore stores category list queries as `['categories', 'list', params, tenantId, companyId]` via `categoryKeys.list()` and `tenantScopedKey([...categoryKeys.list(params)])` (`apps/web/src/features/categories/hooks/useCategories.ts:41`, `apps/web/src/features/categories/hooks/useCategories.ts:61`). But create/delete invalidate `tenantScopedKey([...categoryKeys.all])`, which becomes `['categories', tenantId, companyId]` (`apps/web/src/features/categories/hooks/useCategories.ts:33`, `apps/web/src/features/categories/hooks/useCategories.ts:109`, `apps/web/src/features/categories/hooks/useCategories.ts:145`). TanStack Query prefix matching compares array positions: position 0 matches (`'categories'`), but position 1 is `tenantId` in the invalidation key and `'list'` in the leaf key, so the list query is not matched. The same positional mismatch prevents `categoryKeys.all` invalidations from reaching tree/detail leaves, and prevents `categoryKeys.lists()` invalidations from reaching list leaves because `['categories', 'list', tenantId, companyId]` mismatches `['categories', 'list', params, tenantId, companyId]` at position 2 (`apps/web/src/features/categories/hooks/useCategories.ts:129`, `apps/web/src/features/categories/hooks/useCategories.ts:164`). This breaks at least create/delete all-query invalidation and update/reorder list invalidation.

[F2] The new mutation invalidation test is not an honest regression test for the cache behavior in F1. It replaces `queryClient.invalidateQueries` and records only `arg.queryKey` (`apps/web/src/features/categories/hooks/__tests__/useCategories.tenantScope.test.tsx:197`, `apps/web/src/features/categories/hooks/__tests__/useCategories.tenantScope.test.tsx:199`, `apps/web/src/features/categories/hooks/__tests__/useCategories.tenantScope.test.tsx:200`), then asserts seven calls and that each recorded key contains the tenant and company strings (`apps/web/src/features/categories/hooks/__tests__/useCategories.tenantScope.test.tsx:225`, `apps/web/src/features/categories/hooks/__tests__/useCategories.tenantScope.test.tsx:227`, `apps/web/src/features/categories/hooks/__tests__/useCategories.tenantScope.test.tsx:235`). Because it never seeds matching category queries, observes refetches, or asserts actual cache invalidation, the test passes while the prefix-match cascade in F1 is broken.
