### HIGH

- [apps/api/database/migrations/tenant/2026_06_22_100000_backfill_partner_liability_balance_sign.php:32] `up()` is not idempotent and is destructive on replay: the first run converts an old `-50.0000` liability cache to `50.0000`, but a second run enters the `ELSE 0` branch at line 35 and zeroes the now-correct magnitude. The same hazard applies to `payable_balance`. Normal Laravel migration bookkeeping should prevent routine double execution, but the migration body itself is not safe if replayed directly, retried outside the migrations table, or invoked the way the test invokes it at `apps/api/tests/Feature/Accounting/BackfillPartnerLiabilityBalanceSignTest.php:87`.
- [apps/api/database/migrations/tenant/2026_06_22_100000_backfill_partner_liability_balance_sign.php:41] `down()` is lossy and not a correct inverse of `up()`: `up()` deliberately clamps any pre-existing positive value to zero at line 35, and `down()` then only multiplies the remaining value by `-1` at line 48, so an original positive anomaly cannot be restored. This may be acceptable for a rebuildable cache, but it is not a safe inverse and should be documented as irreversible or replaced with a GL-derived recomputation.
