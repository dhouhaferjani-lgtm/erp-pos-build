## Reading the matrix

- **Drive** — `UI` = through the browser (**mandatory for the happy path of every class**), `API` = `apiRequest(page, …)` shape probe, `SQL` = `psql` against `tenant_<uuid>`.
- **Oracle** — the `path:line` that *defines* the expectation. A row with no oracle is not gate-ready; **[r2] neither is a row that declines to state a determinate expectation** (r1 had three such rows; all are now pinned).
- Every expected figure is computed by hand and marked **[derived]** — none executed. The run turns each into **[measured]** in the evidence doc.
- A figure that depends on an unresolved owner ruling is marked **[RULING]** and is recorded, not asserted.
- **Every scenario** asserts zero `5xx` on `page.on('response')` and zero console errors except the single tolerated `/auth/me` 401 on `/login` (until lane K-10 merges), named explicitly wherever tolerated.

### THE COSTING RULE  [r2 — gate BLOCKER G1-C1-01]

> **WAC is a running, company-wide average persisted on `products.cost_price` (`WeightedAverageCostService.php:100-128` denominator, `:241-253` blend, `:291` write-back). No absolute cost or stock figure below is valid unless its product is used exactly once in the run.**

r2 therefore gives **every WAC-asserting class its own virgin product**, so all the arithmetic both reviewers verified stays byte-identical. The same rule applies to purchase orders: **no PO is reused across classes** (r1's second-location class re-received a `PO-C` that the partial-receipt class had already closed).

## Tolerances

- **Zero 5xx.** Every browser probe registers `page.on('response')` and fails the leg on any `status >= 500`. **[r2] two rows are permitted to *record* a 5xx as a finding while still failing their leg**: `W2-EDGE-1` (non-UUID route param) and `W2-EDGE-11` (over-long `batch_number`). Note that `PurchaseOrderController.php:857-865` converts **every** `QueryException` in the receive path into a 500, so an unexpected 5xx there is a DB-level failure, not a logic branch.

- **No `toBeCloseTo`, ever.** Money and quantity compare as strings via `assertMoneyEqual`; 6-dp costs compare as exact strings read from Postgres.
