# Imports hardening — Phase 1 gap matrix (Session G, 2026-08-29)

Session G is the owner-mandated hardening pass over the whole unified-imports flow (`docs/modules/imports.md`, `ImportService`/`MigrationWizardService`/`ResultWorkbookService`, `import_jobs`/`import_rows`, and the FE wizard at `apps/web/src/features/import/`). This document synthesizes six read-only Phase-1 audits (A — idempotency/natural keys, B — transparency/history/export, C — wizard flow/preview/UX, D — SKU scope census, E — templates/locale/type-coverage, F — customers/suppliers split feasibility) plus the owner's requirements in `docs/sessions/session-G-imports-hardening-2026-08-29/HANDOVER.md`, into a single requirement↔exists↔gap matrix and a proposed lane map for Phase 3. Method: each audit worked read-only against `dev` baseline commit `a4ceeb0f5`, and every claim below preserves its source audit's `path:line` citation verbatim rather than re-deriving it. The six audit files and the handover live under `docs/sessions/session-G-imports-hardening-2026-08-29/`, which is **gitignored** (ephemeral session workspace) — this document is therefore the sole tracked record of Phase 1 and is written to stand on its own without needing those source files to be readable. Session F's Lane F1 (worktree `.worktrees/f-bug-1`, branch `fix/f-bug-1-import-location`) owns triage items 1a/1b/1c/1e from its own brief (default-location backfill, a wizard stock-location select, a completion-step warning panel, and `location_code`/`placement_path` label hints in en/fr/ar) and, as of this audit, had written no code yet (`git -C .worktrees/f-bug-1 status --short` empty, `log --oneline -1` = `a4ceeb0f5`) — those items are excluded from Session G's gaps below except where noted.

## 2. Findings register (the things the owner did not ask for but the audits found)

Severity: **P1** = tenant #1 testers hit it today, or a data-integrity / silent-money-error risk. **P2** = real hardening gap, not yet observed in production. **P3** = hygiene/drift, low risk.

1. **Async ≥100-row imports have no failed-rows download** — P1 — `failed_rows_csv_url` is only populated on the synchronous (<100-row) branch (`ImportController.php:531-535` vs `:568-571`); the wizard's completion step gates its button on that field (`ImportWizardPage.tsx:1074-1086`) — every real catalogue load (≥100 rows) offers no export at all. — **G-1**
2. **Stuck `importing` jobs have no reaper** — P1 — a worker SIGKILL/OOM/restart never calls `failed()`; nothing sweeps a job frozen in `importing` (`grep -rln "Importing\b" app/` → Import module only); the job becomes permanently un-executable (execute requires `Validated|Pending`) and the wizard polls forever (`ProcessImportJob.php:51,56,131-134,308`; `ImportWizardPage.tsx:379-386`). — **G-6**
3. **Result workbook "Imported" sheet ignores `is_imported`** — P1 — the query is `is_valid=true AND import_error IS NULL`, with no `is_imported` check, so a merely-validated-but-not-yet-executed job, or a row demoted by a post-loop finalize phase, is reported as Imported (`ResultWorkbookService.php:22-25`); can directly contradict the job's own `successful_rows` counter. — **G-1**
4. **Raw SQLSTATE surfaces in 3 places / no error-code channel** — P2 — `import_error = $e->getMessage()` verbatim on both sync and async paths, rendered inline in `ValidationGrid.tsx:122-125`, exported verbatim in the failed-rows CSV and the result workbook; no `import_error_code` column exists anywhere (`ProcessImportJob.php:169-175`; `ImportService.php:360-366`; `FailedRowsExportService.php:133-135`; `ResultWorkbookService.php:126-133`). — **G-1**
5. **`location_unresolved` wording is untruthful for the no-code case** — P2 — one fixed detail string covers two different causes (no code supplied at all vs. a code that couldn't be resolved), is false for the majority staging case (nothing "could not be resolved" because nothing was given), and never states the consequence (no stock created) (`ProductOpeningStockPhase.php:79,243-255`). F1's completion-step warning panel is expected to cover the "no stock created" surfacing; the code/wording split itself is G's. — **G-1**
6. **`import_jobs` has no `company_id` and no file hash** — P1 — jobs are tenant-scoped only, retargeted at every phase from ambient `CompanyContext`; nothing pins a job to the company it was previewed against, and nothing deduplicates a re-upload of the same file (`2025_11_30_150000_create_import_tables.php:14-33`). — **G-3b**
7. **`partners.vat_number` is tenant-wide unique while the lookup is company-scoped** — P1 — the identical 1d shape as products; a second company importing the same supplier list with a `tax_id` raises a raw 23505 (`2025_11_30_052119_create_partners_table.php:34`, not touched by the 2025-12-30 fix migration). — **G-3a**
8. **`product_variants` carries the same tenant-wide risk one layer down** — P2 — `unique(tenant_id,sku)` and `unique(tenant_id,barcode)` via raw `DB::statement`, PG-only (`2026_06_02_100003_create_product_variants_table.php:37-40`); unlike `products`, the application code is already company-scoped and only the DB constraint lags. — **G-3a**
9. **`ProductImageImportService.php:238` matches SKU tenant-wide + `CreateProductRequest`/`UpdateProductRequest` unique rules are tenant-scoped only** — P2 — an image can attach to another company's product in a multi-company tenant; the two FormRequest `Rule::unique` calls will produce a false-negative "SKU available" once the DB unique moves to company scope unless updated in the same lane (`CreateProductRequest.php:177-184`; `UpdateProductRequest.php:162-169`). — **G-3a**
10. **Thinner re-import NULLs previously-populated columns** — P1 — products: `purchase_price`, `barcode`, `unit`, `description` are written from the row even when blank because `emptyToNull()` always carries the key (`ProductService.php:65-74,313-320`); partners: the upsert rewrites address/contact fields unconditionally including with `null` (`PartnerService.php:90-106`) — becomes a live risk under R9's split (F's R9). — **G-4**
11. **`tax_rate` preserved on blank = field-level merge, not literal override** — P3 — a deliberate carve-out that must be stated explicitly in any R4 "newer overrides" copy, since it is not actually a full overwrite today (`ProductService.php:99-113`). — **G-4**
12. **No SKU generator; name-slug fallback collides; user never told; UI create path still requires SKU; docs say required** — P2 — `docs/modules/imports.md:147-149,165` directly contradicts the code and R2. — **G-2**
13. **Ambiguous `1,234` always parsed European = silent 1000× error for a US/UK company** — P1 — hardcoded, undocumented as country-derived, no warning, no row error, nothing in the result workbook (`NumericFieldNormalizer.php:18-20,76-78`). — **G-8**
14. **Template is CSV-only, no BOM, dot-decimal samples, hardcoded `,` delimiter** — P2 — see R8 gap detail. — **G-8**
15. **`composite_items` has zero test coverage; only legacy `partners` has a true HTTP round-trip E2E** — P2 — a live, selectable import type shipped with no validation/execution/template test at all. — **G-7**
16. **Two live partner importers, `partners` + `parties`** — P2 — the root of the owner-described confusion; both selectable, both on the dashboard (Audit F §A.1). — **G-9**
17. **`finalizeImport()`'s `default => []` trap** — P1 — a new `ImportType` case that forgets its finalize arm compiles and runs cleanly while silently never posting GL/AR/AP postings; not compiler-caught (`ImportService.php:466-471`). — **G-9**
18. **Wizard job is not resumable / no `DELETE` route but a dead `useDeleteImport` hook exists** — P2 — `jobId` is React state with no URL segment, so any refresh past mapping abandons the server-side job; the FE ships a delete client (`importApi.deleteJob`, `useDeleteImport`) that would 405 because no `DELETE` route exists (`ImportWizardPage.tsx:226`; `routes/index.tsx:2416`; `importApi.ts:105-107`; `ImportServiceProvider.php:71-88`). — **G-6**
19. **Error grid capped at 50 rows silently; fix-in-place unwired** — P2 — `useImportErrors` fetches with no page/perPage, hitting the server's default 50-row cap with `meta` discarded — a 900-bad-row file shows 50 and says nothing about the rest; `ValidationGrid`'s `onRowUpdate` prop exists but is never supplied at either call site, and no endpoint would persist an edit anyway (`queries.ts:61`; `ImportController.php:320-321`; `ValidationGrid.tsx:11,140-153`). — **G-10**
20. **`ColumnMapper` never renders `description`** — P3 — the W4-1 per-column-help residual is CONFIRMED still unbuilt: `TARGET_COLUMNS` carries a `description` for many columns, typed on `ColumnMapper`'s props, never read (`ImportWizardPage.tsx:126-202`; `ColumnMapper.tsx:10`). `location_code` and `quantity` — exactly the two columns the staging team misread — have no description at all. — **G-10**
21. **Arabic locale is 15/185 keys; `wizard.progressAriaLabel` key is missing** — P2 — the entire wizard, history page, statuses and messages fall back to English for Arabic operators; the aria-label key is nested one level too deep in en/fr so it never resolves in any locale (`apps/web/src/locales/*/import.json`; `ImportProgress.tsx:25`). — **G-10**
22. **History page: no pagination/detail/company/operator/error_message** — P2 — see R6 gap detail. — **G-6**
23. **Docs drift: statuses `processing`/`partially_completed` don't exist, `validated` missing** — P3 — `docs/modules/imports.md:66-80` documents a state machine the code does not have (`ImportStatus.php:9-14`). — **G-6**
24. **`countries.default_locale` is dead data; `CountryDefaults` has no number-format concept** — P3 — the one seeded locale signal has exactly one unrelated consumer (`AuthController.php:931`); nothing reads it for import purposes. — **G-8**
25. **`customer_category` is wired end-to-end but never written by any importer or by POS walk-in creation** — P2 — the column, enum, DTO and request rule all exist and are load-bearing for fiscal B2B escalation, but `PartnerService::upsertWithTypeMerge()`'s update payload never sets it, so every imported customer inherits `null` (`PartnerService.php:88-107`; `PosPendingCustomerController.php:82-94`). — **G-9**
26. **`hasDownstreamMovements()` exists but the import never calls it** — P1 — see R5 gap detail; this is the single blocking gap for R5. — **G-5**
