## Why

The staging web bundle is a separate Dokploy deploy (`autoDeploy=false`) and sat 78 commits stale undetected on 2026-07-04 (`docs/factory/WORKFLOW.md:220-227`). The staging push manifest §3 verifies a deploy with an asset-hash diff plus a grep for a slice-unique string, and §6 U-4 records that `/build-fingerprint.json` does **not** exist while sibling plans already require `build_sha` from it. This lane makes it exist so §3 becomes a two-line check.

There is no JSON-specific location, so a `.json` under `/` would be served via `try_files` **without** a cache header (browser heuristics apply) — a fingerprint must be `no-store`.
- No `.git` in the builder → the sha cannot be read from git at build time; it must arrive as a build arg. Whether Dokploy passes the commit sha as a build arg is **UNVERIFIED** (manifest §6, new row U-9). Fallback must be explicit (`"unknown"`), never a fabricated value.
- `scripts/factory/manifests/routes-web.yaml` is the checked-in web route manifest (regenerated by tooling; last regen `3df25b94f`). It is a stable, reviewable source for a *feature* fingerprint.
- `apps/web/tools/__tests__/*.test.mjs` is the vitest lane for build tooling (`package.json:13` `test:tools`).
- `apps/web/public/` is committed (favicon, vite.svg); `dist` is gitignored. A generated file must go to `dist/` at build time or be gitignored under `public/`.

## Scope

1. **Generator** `apps/web/tools/write-build-fingerprint.mjs` (ESM, no `__dirname`, no `any`): writes `dist/build-fingerprint.json` AFTER `vite build` (so it is not in the hashed asset graph and is never stale relative to `dist`). Fields:
   - `build_sha`: first non-empty of `BUILD_SHA`, `VITE_BUILD_SHA`, `SOURCE_COMMIT`, `GIT_SHA`, `git rev-parse HEAD` when a `.git` is reachable (local builds), else `"unknown"`.
   - `build_time`: ISO 8601 UTC.
   - `product`: `VITE_APP_PRODUCT` (`izipos` default, `otospex`).
   - `feature_fingerprint`: sha256 (first 16 hex) of the sorted route paths read from `scripts/factory/manifests/routes-web.yaml` (path resolved from `import.meta.url` to the repo root; if the file is absent, `"unknown"` and a non-zero exit **in CI only** — set by `CI=true`).
   - `route_count`: integer.
   - `schema`: `1`.
2. **Build wiring**: `package.json` `build` → `tsc -b && vite build && node tools/write-build-fingerprint.mjs`. Dockerfile: `ARG BUILD_SHA` + `ENV BUILD_SHA=$BUILD_SHA` in the builder stage next to the existing Vite args (`Dockerfile:50-54`), and a comment that Dokploy must pass `BUILD_SHA` as a build argument (U-9).
3. **Serving**: in `apps/web/docker/entrypoint.sh`, add `location = /build-fingerprint.json { add_header Cache-Control "no-store, no-cache, must-revalidate" always; try_files $uri =404; }` before `location /` (mind the shell escaping style used at `:172-173`).
4. **Optional read in the app**: none. Do not import the file into the bundle (it would bake the sha into the hashed graph and defeat the stale-bundle check).
5. **Manifest update** `docs/superpowers/plans/2026-09-06-parapharmacy-staging-push-manifest.md`: §3 replace the sentence "There is **no** `/build-fingerprint.json` in this repo (§6 U-4); do not plan around one." with the verification block:

   ```bash
   curl -s https://erp.otospex.dev/build-fingerprint.json | tee /tmp/<slice>-fingerprint.json
   jq -r '.build_sha' /tmp/<slice>-fingerprint.json      # MUST equal the promoted CANDIDATE_SHA; "unknown" == U-9 not closed
   jq -r '.feature_fingerprint' /tmp/<slice>-fingerprint.json   # MUST equal `node apps/web/tools/write-build-fingerprint.mjs --print-fingerprint` at CANDIDATE_SHA
   ```
   Keep the asset-hash + grep pair as the fallback while U-9 is open. §6: close U-4 (implemented, cite files), add **U-9** "Dokploy passes `BUILD_SHA` build arg to the web build" with the verification "fingerprint `build_sha` ≠ `unknown` after one deploy".
6. **Tests** (red first): `apps/web/tools/__tests__/write-build-fingerprint.test.mjs` — env precedence (`BUILD_SHA` > `VITE_BUILD_SHA` > `SOURCE_COMMIT` > git > unknown), deterministic `feature_fingerprint` for a fixture manifest (`tools/__fixtures__/routes-web.sample.yaml`), output shape/schema, `--print-fingerprint` prints only the hash, no-manifest behaviour (unknown locally, exit 1 with `CI=true`). Add a Dockerfile/entrypoint smoke to the handback: `docker build -f apps/web/Dockerfile --build-arg BUILD_SHA=$(git rev-parse HEAD) -t web-fp .` **only if** the laptop has headroom (swap < 9 GB); otherwise run the generator against a local `pnpm build` and `sh -n apps/web/docker/entrypoint.sh` for syntax.
