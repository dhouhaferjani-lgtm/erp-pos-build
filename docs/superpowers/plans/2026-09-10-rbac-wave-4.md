### Q-w4-3 — the campaign is a SECOND campaign, not legs appended to the onboarding one

`docs/qa/ONBOARDING-CAMPAIGN.md` is the fresh-tenant promotion gate, with legs L0a..L9 and its own known-red list; a red campaign blocks promotion and *"promotion reads the ledger, not the exit code"*.

**This plan implements a separate `scripts/campaign-rbac.sh` with its own config, ledger and runbook**, copying the onboarding campaign's shape verbatim. Three reasons: the onboarding campaign registers **one** tenant per run and is throttled (5 registrations per window per IP, ~576 migrations synchronously in-request, 20–60 s), so appending forty legs to it makes one run enormous and one red anywhere block both gates; its fixtures are **Tunisia/Parapharmacy-only** and this campaign needs a **second company and a second `pos_enabled` location**, which the onboarding fixtures do not create; and its known-red list is about product findings in the money path, which would drown an authorization finding.

**The bounded alternative** — one campaign, RBAC as legs L10+ — is a real option and costs less scaffolding; it is rejected because it couples two promotion gates whose failure modes are unrelated. **If the orchestrator prefers coupling, the edit is bounded**: move the nine browser legs into `apps/web/e2e/campaign/` as L10..L18, add their ledger definitions to the existing `journey.ts`, and drop `campaign-rbac.sh`. Nothing else changes.

**Separate JOURNEYS, one RUNNER.** Rev 1 duplicated the argument parsing, the preflights, the run-id generation and the ledger mechanics as well as the journey, which is a second implementation of the same campaign protocol (plan gate r1, **MAJOR M4-2**). Separate gates, ledgers and known-red lists are the point and stay separate; **the plumbing does not**. `scripts/campaign-lib.sh` is extracted from `dev:scripts/campaign-onboarding.sh:3-63` and sourced by both, with `CampaignLibParityTest` proving the onboarding campaign's observable behaviour is unchanged by the extraction. Where an orchestrator would rather not touch a live promotion gate at all, the fallback is the **explicit version contract** described in the File Structure's *Modified* table — `CAMPAIGN_LIB_VERSION`, asserted equal by both — and a follow-up lane for the re-point. **What is not acceptable is two silently-diverging copies**, because the first thing to diverge is the exit-code contract, and *"promotion reads the ledger, not the exit code"* only works while both agree on what a ledger is.

### Q-w4-4 — the campaign's tenant is a **campaign tenant**, and there is no teardown

The onboarding campaign records this honestly and it applies identically here: **there is no teardown** — every run leaves its `tenant_<uuid>` database behind under db-per-tenant. `CAMPAIGN_KEEP_TENANT=1` only **prints** the credentials.

**This plan implements the same contract and states it in the runbook**: cleanup of accumulated campaign tenants is an **operator task** (`tenants:list` → delete the `rbac-campaign+…@test.otospex.dev` tenants), and the **push trigger stays INERT** — do not arm a push→dev trigger on a target you cannot clean. The bounded alternative — a teardown command — is genuinely useful and genuinely out of scope for a campaign wave; it is recorded as a residual.

**No teardown is also why the campaign is single-run-per-fresh-tenant rather than idempotent** (Global Constraints, **B4-2**). The two properties are the same fact seen from either end: a run that cannot clean up after itself must not be asked to run again on its own leavings. `--reuse` therefore refuses a multi-leg run outright — `exit 2`, `reason=reuse_is_single_leg` — rather than documenting a caveat a tester can step past, which is the one place this campaign deliberately goes further than the onboarding one.

### Q-w4-5 — which rows can be driven in a browser at all

Of the enumerated ids, only a minority have a **UI** that can express them. The rest are console, database-state or concurrency scenarios whose only honest home is a test lane.

**This plan implements the split by asking one question per row: *can an operator observe this in the product?*** If yes → a browser leg (and, where the underlying rule also needs a unit-level proof, **both**). If no → a lane test, and the evidence document records the **command and its output**, which is the same standard of proof. **What this plan refuses to do is invent a UI for a row so that it can be "campaigned"** — a screen that exists only to make an edge case observable is a second surface (convention 11) and a maintenance burden.

**A third answer exists and rev 1 did not use it: *observable, but not by this harness*.** `R9` was written as a Playwright leg driving *"the dev IziPOS build"*, but the declared config is `apps/web`'s, it preflights only the API and web, it has no `webServer` for a POS target, and **`apps/pos` has no Playwright dependency and no Playwright script at all** (`apps/pos/package.json` scripts are `"test": "vitest run"` and its siblings — plan gate r1, **MAJOR M4-1**). Standing up a Tauri driver is a piece of work in its own right and it is not this wave's.
**So `R9` is declared `NOT_SCRIPTABLE`, with a reason, and EC-31 is covered by two things instead**: `apps/pos/src/lib/auth/__tests__/offlineRevocation.test.ts` (the device logic, automated) and `docs/qa/RBAC-POS-DEVICE-REPLAY.md` (the operator-visible half, a **documented manual replay** whose observations land in the evidence document's own rows). `NOT_SCRIPTABLE` with a named reason and a manual replay is honest; a Playwright leg that cannot run is not. The lane assignments below are the spec's own, with the browser column added.

- [ ] **Step 4 — write `apps/api/tests/EdgeCases/rbac-campaign-manifest.yaml`, the row → lane → command → evidence map.** Rev 1 said *"existing tests are referenced, not copied"* and then gave the runner a command that ran only the **new** directory, one Redis test and two broad frontend folders — so most existing EC homes had no command at all and the script's promise to run *"the PHPUnit lanes"* was unbacked (plan gate r1, **BLOCKER B4-3**).

      2. **`scripts/campaign-rbac.sh` — the manifest-driven runner, in full.**

      ~~~bash
      #!/usr/bin/env bash
      #
      # scripts/campaign-rbac.sh — the RBAC edge-case campaign runner.
      #
      # It sources scripts/campaign-lib.sh for the primitives the onboarding campaign
      # already has (arg-parse skeleton with its two-arg guard and unknown-argument
      # `exit 2`, the two curl --fail preflights, run-id generation, the env exports and
      # the exit-code contract). Everything below --lanes is THIS campaign's and is not
      # part of that extraction (gate r2, MAJOR 4; gate r3, W4 MAJOR 2).
      #
      # EXECUTION MODEL (gate r2 B4; gate r3 W4 BLOCKER 3 — this is the implementation,
      # not the prose):
      #   1. collect every homes[] element across every row
      #   2. partition into leg references and lane commands
      #   3. DEDUP the leg references by leg id, preserving the legs: block's order, and
      #      run each leg exactly ONCE, attributing its result to every referencing row
      #   4. dedup identical (lane, command) pairs
      #   5. execute ACCUMULATING, never short-circuiting; exit non-zero at the end if red
      #   6. never run a destructive: true leg twice; --reuse refuses one unless --leg names it

      set -uo pipefail

      REPO_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
      # shellcheck source=scripts/campaign-lib.sh
      . "${REPO_ROOT}/scripts/campaign-lib.sh"

      MANIFEST="${REPO_ROOT}/apps/api/tests/EdgeCases/rbac-campaign-manifest.yaml"
      LANES=""
      ONLY_ROW=""
      ONLY_LEG=""
      REUSE=0
      STAGING_REPLAY=0
      SSH_TARGET=""
      REMOTE_ROOT="/var/www/autoerp"
      API_CONTAINER=""
      STAGING_TENANT=""

      die2() { echo "$1" >&2; echo "reason=$2" >&2; exit 2; }

      while [[ $# -gt 0 ]]; do
        case "$1" in
          --api|--web|--country)
            campaign_lib_consume_pair "$@"; shift 2 ;;
          --manifest|--lanes|--row|--leg|--ssh|--remote-root|--api-container|--staging-tenant)
            [[ $# -lt 2 || -z "${2:-}" ]] && die2 "Missing value for $1" "missing_value"
            case "$1" in
              --manifest)       MANIFEST="$2" ;;
              --lanes)          LANES="$2" ;;
              --row)            ONLY_ROW="$2" ;;
              --leg)            ONLY_LEG="$2" ;;
              --ssh)            SSH_TARGET="$2" ;;
              --remote-root)    REMOTE_ROOT="$2" ;;
              --api-container)  API_CONTAINER="$2" ;;
              --staging-tenant) STAGING_TENANT="$2" ;;
            esac
            shift 2 ;;
          --reuse)          REUSE=1; shift ;;
          --staging-replay) STAGING_REPLAY=1; shift ;;
          *)
            echo "Unknown argument: $1" >&2
            echo "Usage: $0 [--web URL] [--api URL] [--country TN] [--manifest PATH] [--lanes a,b]" >&2
            echo "          [--row EC-n] [--leg Rn] [--reuse] [--staging-replay --ssh USER@HOST" >&2
            echo "          --remote-root PATH --api-container NAME --staging-tenant UUID]" >&2
            exit 2 ;;
        esac
      done

      # ---- flag contracts (gate r2 B2, B5) -----------------------------------------
      if (( REUSE )); then
        [[ -z "$ONLY_LEG" ]] && die2 "--reuse requires --leg" "reuse_requires_leg"
        [[ "$ONLY_LEG" == *,* ]] && die2 "--reuse takes exactly one leg" "reuse_is_single_leg"
      fi
      if (( STAGING_REPLAY )); then
        [[ -z "$SSH_TARGET" ]] && die2 "--staging-replay requires --ssh" "staging_replay_requires_ssh"
        [[ -z "$API_CONTAINER" ]] && die2 "--staging-replay requires --api-container" "staging_replay_requires_container"
        [[ -z "$STAGING_TENANT" ]] && die2 "--staging-replay requires --staging-tenant (the DISPOSABLE staging tenant)" "staging_replay_requires_tenant"
      fi
      [[ -f "$MANIFEST" ]] || die2 "Manifest not found: $MANIFEST" "manifest_missing"

      campaign_lib_preflight            # the two curl --fail health checks + run id + exports
      RUN_DIR="${REPO_ROOT}/apps/web/test-results/campaign-${CAMPAIGN_RUN_ID}"
      mkdir -p "$RUN_DIR"
      LEDGER="${RUN_DIR}/ledger.json"
      : > "${RUN_DIR}/ledger.ndjson"

      # ---- step 1-4: the manifest becomes a deduplicated, ordered execution plan ----
      # TSV: kind \t key \t lane \t cwd \t env(space-joined) \t rows(comma) \t command
      plan() {
        ( cd "${REPO_ROOT}/apps/api" && MANIFEST="$MANIFEST" ONLY_ROW="$ONLY_ROW" ONLY_LEG="$ONLY_LEG" php -r '
          require "vendor/autoload.php";
          $m = Symfony\Component\Yaml\Yaml::parseFile($_SERVER["MANIFEST"]);
          $onlyRow = $_SERVER["ONLY_ROW"] ?? ""; $onlyLeg = $_SERVER["ONLY_LEG"] ?? "";
          $legs = []; foreach ($m["legs"] as $l) { $legs[$l["id"]] = $l; }
          $legOrder = array_keys($legs);
          $legRows = []; $laneCmds = []; $manual = [];
          foreach ($m["rows"] as $row) {
            if ($onlyRow !== "" && $row["id"] !== $onlyRow) { continue; }
            foreach ($row["homes"] as $h) {
              if (isset($h["leg"])) {                       // step 2/3: leg reference
                if (! isset($legs[$h["leg"]])) { fwrite(STDERR, "unknown leg {$h["leg"]} on {$row["id"]}\n"); exit(2); }
                $legRows[$h["leg"]][] = $row["id"];
              } elseif (($h["lane"] ?? "") === "manual") {  // never executed; recorded
                $manual[] = [$row["id"], $h["result"] ?? "NOT_RUN", $h["doc"] ?? ""];
              } else {                                      // step 4: (lane, command) pair
                $laneCmds[$h["lane"]."\x1f".$h["command"]][] = $row["id"];
              }
            }
          }
          // step 3: dedup by leg id, DECLARED ORDER, each exactly once.
          foreach ($legOrder as $id) {
            if ($onlyLeg !== "" && $id !== $onlyLeg) { continue; }
            if ($onlyLeg === "" && $onlyRow !== "" && ! isset($legRows[$id])) { continue; }
            if ($onlyLeg === "" && $onlyRow === "" && ! isset($legRows[$id]) && ($legs[$id]["covers"] ?? []) !== []) { continue; }
            $lane = $m["lanes"][$legs[$id]["lane"]];
            printf("LEG\t%s\t%s\t%s\t%s\t%s\t%s\n", $id, $legs[$id]["lane"], $lane["cwd"],
              implode(" ", $lane["env"] ?: []), implode(",", $legRows[$id] ?? []), $legs[$id]["command"]);
          }
          foreach ($laneCmds as $key => $rows) {
            [$laneName, $cmd] = explode("\x1f", $key, 2);
            if ($onlyLeg !== "") { continue; }              // --leg runs the leg, nothing else
            $lane = $m["lanes"][$laneName];
            printf("LANE\t%s\t%s\t%s\t%s\t%s\t%s\n", $laneName."/".substr(sha1($cmd), 0, 8), $laneName,
              $lane["cwd"], implode(" ", $lane["env"] ?: []), implode(",", $rows), $cmd);
          }
          if ($onlyLeg !== "") { $manual = []; }   // --leg runs that leg and nothing else
          foreach ($manual as [$rowId, $result, $doc]) {
            printf("MANUAL\t%s\t%s\t%s\t%s\t%s\t%s\n", $rowId, "manual", ".", "", $rowId, $result." ".$doc);
          }
        ' )
      }

      # ---- the staging execution target for a lane (gate r2 B5; gate r3 W4 BLOCKER 5) ----
      # ISOLATION IS MANDATORY. Read-only lanes run against the deployed tree as-is; every
      # MUTATING lane runs ONLY against the disposable staging tenant named by
      # --staging-tenant, on the isolated test databases and on Redis DB 14. A lane with no
      # staging path declares local-only; it never silently runs locally and reports staging.
      staging_wrap() {   # $1 lane  $2 cwd  $3 command  -> prints "TARGET\tcommand"
        local lane="$1" cwd="$2" cmd="$3"
        case "$lane" in
          pg)
            printf 'staging:ssh\tssh %s '\''cd %s/apps/api && DB_DATABASE=autoerp_staging_campaign DB_CENTRAL_DATABASE=autoerp_staging_campaign_central RBAC_CAMPAIGN_TENANT=%s %s'\''' \
              "$SSH_TARGET" "$REMOTE_ROOT" "$STAGING_TENANT" "$cmd" ;;
          redis)
            printf 'staging:ssh\tssh %s '\''cd %s/apps/api && REDIS_DB=14 %s && redis-cli -n 14 INFO server | grep redis_version'\''' \
              "$SSH_TARGET" "$REMOTE_ROOT" "$cmd" ;;
          shell)
            printf 'staging:ssh\tssh %s '\''docker exec %s %s/apps/api/%s'\''' \
              "$SSH_TARGET" "$API_CONTAINER" "$REMOTE_ROOT" "$cmd" ;;
          vitest|posvitest)
            printf 'local-only (declared)\t%s' "$cmd" ;;
          playwright)
            printf 'not replayed — destructive leg, single-run contract\t:' ;;
          manual)
            printf 'staging:manual\t:' ;;
          *)
            printf 'local\t%s' "$cmd" ;;
        esac
      }

      # ---- step 5: execute, ACCUMULATING ------------------------------------------
      red=0
      while IFS=$'\t' read -r kind key lane cwd env rows cmd; do
        [[ -z "${kind:-}" ]] && continue
        if [[ -n "$LANES" && "$kind" == "LANE" && ",${LANES}," != *",${lane},"* ]]; then continue; fi
        if [[ "$kind" == "MANUAL" ]]; then
          printf '{"kind":"manual","row":"%s","result":"%s","execution_target":"manual"}\n' "$rows" "$cmd" >> "${RUN_DIR}/ledger.ndjson"
          continue
        fi

        target="local"; run="$cmd"
        if (( STAGING_REPLAY )); then
          IFS=$'\t' read -r target run < <(staging_wrap "$lane" "$cwd" "$cmd")
        fi

        echo "== ${kind} ${key} [${lane}] rows=${rows} target=${target}"
        started=$(date -u +%Y-%m-%dT%H:%M:%SZ)
        if [[ "$run" == ":" ]]; then
          status=0; result="SKIPPED"
        else
          ( cd "${REPO_ROOT}/${cwd}" && [[ -n "$env" ]] && export $env; cd "${REPO_ROOT}/${cwd}" && eval "$run" ) \
            > "${RUN_DIR}/${key//\//_}.out" 2>&1
          status=$?
          result=$([[ $status -eq 0 ]] && echo PASS || echo FAIL)
        fi
        (( status != 0 )) && red=1
        # A staging-replay row whose target is still `local` is a RED: the lane had no
        # staging path and did not declare one.
        if (( STAGING_REPLAY )) && [[ "$target" == "local" ]]; then result="FAIL"; red=1; fi

        printf '{"kind":"%s","key":"%s","lane":"%s","rows":"%s","result":"%s","exit":%d,"execution_target":"%s","started_at":"%s","output":"%s"}\n' \
          "$kind" "$key" "$lane" "$rows" "$result" "$status" "$target" "$started" "${key//\//_}.out" >> "${RUN_DIR}/ledger.ndjson"
      done < <(plan)

      # One ledger.json, so the evidence document and Task 4-5's re-run read one file.
      # R0 writes .tenant_id into it; Task 4-5 step 2 reads the tenant from there.
      python3 - "$RUN_DIR" <<'PY'
      import json, sys, pathlib
      d = pathlib.Path(sys.argv[1])
      entries = [json.loads(l) for l in (d / "ledger.ndjson").read_text().splitlines() if l.strip()]
      out = d / "ledger.json"
      prev = json.loads(out.read_text()) if out.exists() else {}
      prev["entries"] = entries
      out.write_text(json.dumps(prev, indent=2) + "\n")
      print(f"Ledger: {out}  entries={len(entries)}  red={sum(1 for e in entries if e.get('result')=='FAIL')}")
      PY

      echo "RBAC campaign run-id: ${CAMPAIGN_RUN_ID}"
      exit "$red"
      ~~~

      > **Reading the YAML with `symfony/yaml` from `apps/api/vendor` rather than `yq`** is deliberate: `yq` is not a repository dependency and is not installed on the staging host, while `symfony/yaml` already is and is the same parser `RbacCampaignManifestCoverageTest` uses. **One parser, one truth** — a runner and a test that disagree about the manifest is the worst possible failure here.
      > **The plan is emitted as TSV and consumed by one `while read` loop**, so the dedup happens **once**, in the PHP that can see the whole file, rather than being re-derived in shell per row. `--row` filters rows, `--leg` runs exactly one leg and nothing else, `--lanes` filters lane commands but never legs.
      > **`execution_target` is written into every ledger entry**, and a staging-replay entry whose target is still `local` is forced to `FAIL` — the lane had no staging path and did not declare one, which is precisely the silent-success failure **B5** is about.
      > **Accumulation, not short-circuit:** `red=1` is set and the loop continues; the script exits non-zero at the end. *"Promotion reads the ledger, not the exit code"* is unusable if the first red stops the run.

      3. **`--reuse` requires `--leg` and takes exactly one** (`exit 2` with `reason=reuse_requires_leg` / `reuse_is_single_leg`), and **`--leg` with an unknown id** is `reason=unknown_leg` — raised by the plan builder, which is where the declared leg ids are known.
