## Section 3 — T1.0 scope (single sub-step, configurable SCALE)

### The bug (still present on dev — verified 2026-05-08)

`ParapharmacySeeder::seedProducts` uses a hardcoded `$distribution` array (6 categories × fixed counts = 1000 products). To produce 5000 SKUs the only options today are: (a) manually rewrite the counts (regresses every existing test that depends on 1000), or (b) run the seeder five times (creates duplicate companies/tenants). Neither is acceptable.

### Fix contract

- Add a `SCALE` class constant (`private const SCALE = 1;`) to `ParapharmacySeeder`. Default `1` preserves existing behavior.
- Read the scale from a constructor argument OR an env var (`PARAPHARMACY_SEEDER_SCALE`) so callers can override at run time without editing source. **Recommended: env var pattern** — Laravel seeders are typically run with `php artisan db:seed --class=ParapharmacySeeder` and env vars are the cleanest override.
- In `seedProducts`, multiply every category `count` by the resolved scale: `$count = $data['count'] * $scale;`. Log the resolved totals so the operator sees `'✓ Created 5000 products across 6 categories'` when SCALE=5.
- Update the cosmetic info-line `'✓ Created 1000 products across 6 categories'` to reflect the actual count: `'✓ Created '.$totalCount.' products across 6 categories'`.

**Codex preempts:**
- **DB performance.** Inserting 5000 products with their relations (ingredients, certifications, health claims, key components, stock levels) can take noticeable time. The seeder uses individual creates (not bulk insert). For T1.0 this is acceptable — fixture seeding is a one-time operation, not a hot path. Document the runtime in the PR body for transparency.
- **Memory.** Loading reference data (`Ingredient::all()`, `Certification::all()`, `HealthClaim::all()`, `KeyComponent::all()`) at the top of `seedProducts` is fine at 5x scale because reference data doesn't grow with SCALE.
- **Stock levels.** `seedStockLevels` is called with the products collection. At 5x scale that's 5x more stock-level writes — same scaling, same concerns.
- **Test users + partners.** These are seeded ONCE regardless of SCALE — confirm by reading `seedPartners` and `createTestUsers`.

### Out of T1.0 scope (explicit deferrals)

- **Bulk insert refactor** — would speed up large scales but expands the diff and risks regressions. Defer to a future perf-focused PR.
- **Shared SCALE base class** — if other seeders (DemoTenantSeeder, CoffeeShopSeeder) want the same pattern later, extract a trait. Out of scope for T1.0.
- **CSV-driven product import** — would let the fixture grow without code changes. Genuinely out of scope; this is fixture-bump only.
