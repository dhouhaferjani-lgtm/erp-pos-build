        return [
            'sales_order_expiry_days' => $this->salesOrderExpiryDays,

### Issue 3: Event Structure Mismatch ⚠️ MEDIUM PRIORITY

**Problem:** Document uses standard Laravel event pattern, but codebase uses **Spatie Event Sourcing**

**Evidence:**
- Existing events extend `App\Shared\Domain\Events\DomainEvent`
- `DomainEvent` extends `Spatie\EventSourcing\StoredEvents\ShouldBeStored`
- Event sourcing is already integrated with aggregate roots and event store

**Document Pattern (Lines 664-683):**
```php
use Illuminate\Foundation\Events\Dispatchable;
use Illuminate\Queue\SerializesModels;

class ReservationCreated
{
    use Dispatchable, SerializesModels;

    public function __construct(
        public readonly StockReservation $reservation,
        public readonly array $context = [],
    ) {}
}
```

**Correct Pattern (matching existing codebase):**
```php
<?php

declare(strict_types=1);

namespace App\Modules\Inventory\Domain\Events;

use App\Shared\Domain\Events\DomainEvent;

/**
 * Event raised when stock is reserved for a sales order or cart.
 *
 * This event is part of the audit trail for fraud detection.
 * All reservation creations are logged to the event store.
 */
final class ReservationCreated extends DomainEvent
{
    public function __construct(
        public readonly string $reservationId,
        public readonly string $companyId,
        public readonly string $productId,
        public readonly string $locationId,
        public readonly string $quantity,
        public readonly string $sourceType,
        public readonly string $sourceId,
        public readonly ?string $sourceLineId,
        public readonly ?string $expiresAt,
        public readonly string $availableBefore,
        public readonly string $availableAfter,
        public readonly ?string $createdBy,
    ) {
        parent::__construct($reservationId);
    }

    public function getEventName(): string
    {
        return 'stock.reservation_created';
    }
}
```

**Fix Required for ALL events:**
- `ReservationCreated`
- `ReservationReleased`
- `ReservationExpired`

**Why This Matters:**
- Spatie Event Sourcing requires events to be serializable to JSON
- Events are stored in `stored_events` table for audit trail
- Cannot pass full Eloquent models (like `StockReservation $reservation`) as properties
- Must pass primitive types (strings, ints, floats, arrays)

- Use type checking to handle SalesOrder differently

**Recommendation:** Proceed with Option A as proposed in document, but note this is a **NEW PATTERN** being introduced.

### Issue 6: Pending Events Pattern ⚠️ MEDIUM PRIORITY

**Problem:** Document uses `$pendingEvents` array pattern (Lines 847-1079)

**Issue:** This pattern doesn't align with Spatie Event Sourcing, which handles event persistence differently

**Current Pattern in Codebase:**
```php
// Events dispatched directly with event() helper
event(new DeliveryNoteConfirmed($deliveryNote));
```

**Document Pattern:**
```php
// Store for post-commit dispatch
$this->pendingEvents[] = new ReservationCreated($reservation, [
    'available_before' => $available,
    'available_after' => $available - $quantity,
]);

// Later...
public function dispatchPendingEvents(): void
{
    foreach ($this->pendingEvents as $event) {
        event($event);
    }
    $this->pendingEvents = [];
}
```

**Question for User:** Should we:
1. **Keep manual pending events** for explicit control over timing (document approach)
2. **Use Spatie's transaction-aware event dispatching** (simpler, but less explicit)
3. **Hybrid approach** - dispatch after transaction commits using Laravel's `DB::afterCommit()`

**Recommendation:** Use `DB::afterCommit()` for cleaner pattern:

```php
DB::transaction(function () use ($reservation) {
    // ... create reservation ...

    DB::afterCommit(function () use ($reservation) {
        event(new ReservationCreated(
            reservationId: $reservation->id,
            // ... other primitive fields
        ));
    });
});
```
