### 🔴 [ISSUE-008] GL Hash Chain Weakness
**Confirmed.**
- Checked `apps/api/app/Modules/Accounting/Domain/Services/GeneralLedgerService.php`.
- `postEntry()` uses a simple local SHA256 hash.
- It does **not** use the robust `FiscalHashService` used by Documents.
- It does **not** implement the same strict chaining (sequence numbers, pessimistic locking of previous hash).
- This creates a compliance vulnerability where GL entries are less secure than Invoices.

## 3. Architectural Remarks

### On GL Entry Creation (Issue-001)
The report recommends injecting `GeneralLedgerService` directly into `DocumentPostingService`.
- **Alternative considered:** Using a Listener (`CreateGLEntryOnInvoicePosted`).
- **Decision:** I **ENDORSE the report's recommendation (Direct Injection)** over a Listener for this specific case.
- **Reasoning:** Financial integrity requires atomicity. If a Listener fails *after* the invoice is committed, we have a data integrity issue (Invoice Posted but no GL). Wrapping both in the same DB transaction ensures that either both happen or neither happens.

### On Stock Deduction (Issue-002)
The report recommends adding `deductStock` to the `PostCOGSOnInvoice` listener.
- **Review:** This is acceptable provided the listener is synchronous and handles failures gracefully (or retries).
- **Refinement:** Ideally, stock deduction should also be transactional with the invoice posting if we want strict consistency (prevent posting if no stock).
- The report suggests `InsufficientStockException` in `DocumentPostingService` (Task P2-TASK-010). This implies a check *before* posting.
- **Recommendation:**
    1. Check stock availability inside `DocumentPostingService` transaction (lock rows).
    2. Deduct stock inside the same transaction.
    3. If relying on Listener, there is a race condition where stock might disappear between "Check" and "Deduct (in listener)".
    4. **Stronger Recommendation:** The `InventoryService->deductStock()` call should ideally happen **inside the DocumentPostingService transaction**, similar to the GL entry. Relying on an event listener for *core* stock deduction introduces eventual consistency complexities that might not be desired for a simple ERP.

### On Interfaces
The `Shared/Contracts` are indeed too thin.
- `InventoryServiceInterface` needs to expose `checkAvailability(productId, locationId, qty)` and `deductStock(...)`.
- `AccountingServiceInterface` needs `createGLEntry...` methods as suggested.
